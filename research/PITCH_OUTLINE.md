# Структура презентации

Слайд за слайдом: что на нём, какая картинка, какая цифра, что сказать вслух.
Картинки — в `research/pitch_assets/`, имена файлов указаны.

**Про слайды 7–11.** Организаторы требуют их по своему шаблону. Шаблона у нас
нет (см. `docs/TZ_CHECKLIST.md`, раздел 13), поэтому содержание ниже —
предложение, а разметка проставляется, как только шаблон появится. Всё
остальное наше.

**Тайминг.** Рассчитано на 7 минут доклада плюс вопросы: примерно 25 секунд на
слайд, на слайдах 4, 5 и 12 — по минуте.

| Что | Номер нечитаем: ракурс, грязь, блик, перекрытие, нет в кадре. Нужен признак, который работает, когда номера нет |

## 4. Методология и выбор бэкбона *(обязательный блок)*

| | |
|---|---|
| Что | Девять вариантов замерены на одном сплите. Протокол: 150 отложенных машин, кросс-камерный расчёт, совпадения своей камеры исключены |
| Картинка | **`01_backbones.png`** |
| Цифра | **mAP 65.16** у SigLIP base + голова; замена CLIP на SigLIP дала **+27.8 без обучения** |
| Сказать | Два вывода. Первый: выбор бэкбона решает больше, чем тюнинг. Второй: заштрихованные строки — модели на датасетах с закрытой лицензией, мы их замерили как ориентир и в решение не взяли. |

## 5. Проблема ракурса: измерили и закрыли *(обязательный блок)*

| | |
|---|---|
| Что | Сначала назвали проблему числом, потом показали, что с этим числом стало |

### 7. Архитектура решения

| | |
|---|---|
| Что | Кадр → рамка → кроп с запасом 10% → SigLIP → голова → вектор 512D → поиск → отказ или кандидаты |
| Картинка | `11_architecture.png` |
| Цифра | вектор **512 чисел**, веса **359 МБ** при лимите 2048 |
| Сказать | Ничего экзотического: одна модель, одна голова, один индекс. Сложность спрятана в протоколе оценки, а не в схеме. |

### 8. Путь пользователя

| | |
|---|---|
| Что | Оператор загружает кадр, обводит машину, получает кандидатов с уверенностью либо честный отказ. Переключатель строгости |
| Картинка | **`12_user_journey.png`** |
| Цифра | два режима: сбалансированный (порог 0.509) и строгий (0.635) |
| Сказать | Порог — это продуктовое решение, а не константа в коде, поэтому он вынесен оператору. |

### 9. Метрики и режим отказа

| | |
|---|---|
| Что | Качество ранжирования и отдельно качество отказа, с объяснением, почему протоколов два |
| Картинка | **`05_refusal.png`** |
| Цифра | **AUC 0.972**, F1 0.934, TNR 0.927 |
| Сказать | Здесь мы нашли у себя ошибку до жюри: порог, снятый с кросс-камерного распределения, на боевой выдаче не срабатывал ни разу. Перекалибровали на том распределении, в котором реально работает сервис. |

### 10. Производительность

| | |
|---|---|
| Что | Задержка, пропускная способность, память, размер весов |

## Чего в презентации сознательно нет

* Заявки на двукратное ускорение — замер её не подтвердил.
* Метрик на тестовой выборке — меток нет, и придумывать их мы не будем.
* Слова «state of the art». Мы показываем сравнение на своём сплите, а не
  место в чужом рейтинге.
