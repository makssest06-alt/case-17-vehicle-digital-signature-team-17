# TEAM33: restricted per-query k-reciprocal rerank — reference для Gleb

**Для кого:** Gleb (владелец production-постпроцессинга).
**Статус:** knowledge-заметка только. НЕ для реализации в модельной ветке — модельную ветку не трогаем, вся работа по rerank делается в postprocessing-пакете после записи эмбеддингов.

## Формулировка

Ограниченный (restricted) per-query k-reciprocal rerank, в основе — Zhong et al., "Re-ranking Person Re-identification with k-reciprocal Encoding", CVPR 2017.

- Гиперпараметры: `k1 = 6`, `k2 = 3`, `lambda = 0.3`.
- Пул кандидатов: **только** `query + cosine top-50 статической галереи`. g@g отношение вычисляется **исключительно внутри этих 50**, ничего за пределами пула не подтягивается.
- **Нет** cross-query pooling: запросы не смешиваются между собой, каждая строка независима.
- **Нет** внутри скорера: DBA (query expansion), AQE, CSLS, camera-penalty.
- Вне top-50: исходный порядок cosine сохраняется под выбранным блоком (строки за пределами пула не перемешиваются, просто остаются ниже).

## Подтверждение корректности (compliance evidence)

- Юнит-тесты команды доказывают **row-wise independence**: обработка одного запроса не зависит от того, какие ещё запросы в батче (требование стриминга/онлайна выполняется).
- Параметры (6, 3, 0.3) сидят на **выровненном плато** тьюнинга — чувствительность к сдвигам вокруг точки низкая.
- loss при transfer между половинами датасета: **~0.0035–0.0124** (переносимость параметров между половинами, плато, а не переобучение под точку).

## Измерения (на ИХ lenient-сплите)

- Сплит: 1110 запросов × 750 галерейных векторов, оценивается **832** строки; сплит выведен из train-ID (переиспользованный, «мягкий»).
- Косинус: mAP@10 **0.7242** → после rerank: **0.7411** (**+1.7** п.п.), R1: **+0.0228**.
- Стоимость: rerank **0.55–1.8 с** против **69–128 с** эмбеддинг-пасса — rerank копеечный на фоне пересчёта эмбеддингов.
- Порядок в пайплайне: rerank выполняется **ПОСЛЕ записи эмбеддингов**; эмбеддинги **бит-идентичны** во всех режимах (rerank не влияет на модель/эмбеддинги).

## Полезные мелочи

- Порог отказа (refusal) калибруется **отдельно на косинусе**, правило `max–min(TNR, F1)`, на фиксированных долях отказа.
- Шкала ранжирования и шкала отказа **никогда не смешиваются** — два независимых канала.
- NaN-защита: guard на `column_max == 0` (нет не-ИД топлива → не делим на ноль).
- Stable argsort — детерминированный порядок равных значений.
- Батч-прогоны с `--network none` (офлайн, без сети).

## Оговорка про сравнение с нашими числами

Их baseline 0.7242 — на **мягком переиспользованном** сплите: 275 open-set строк **исключены**, в ряды попало **21–33% near-duplicate** moment-рядов.
**Несравнимо** с нашим чистым holdout 0.8666: другой сплит и другая галерея (**357g** у нас против **750g** у них).
Что переносится честно: сам **дельта +1.7** внутри их сплита внутренне консистентна и, скорее всего, переносится на наш пайплайн с небольшим дефлятом (ожидать меньше 1.7, но положительно).
