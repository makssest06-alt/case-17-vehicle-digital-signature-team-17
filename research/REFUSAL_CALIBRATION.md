# Калибровка режима отказа

> **Исторический документ (16.10, артефакты прежнего студента).** Действующий порог 0.8562 / 0.9294 посчитан
> на собственном сплите из `train.csv` без данных теста (`docs/refusal.md`, корневой `README.md`, раздел 4.2).

У нас есть два разных score, которые нельзя смешивать:

- сервис принимает решение по **raw cosine** (`api/app/main.py`);
- `artifacts/postprocess.json` прежнего студента (коммит `322a6e5`) содержал порог для результата
  `qq_expand → k-reciprocal → CSLS`.

Поэтому порог `0.094672` из того артефакта нельзя было подставлять в сервис. С `e81262d` (18.10) артефакты
собираются a10 тем же кодом, что сервис; с `da24136` в `artifacts/postprocess.json` — `score: raw`,
`threshold: 0.7586`, с 20.10 — `0.8562` (отказ без исключения почти-дублей). Организатор сообщил (16.10), что тогдашняя точка давала recall менее 10%, поэтому выбирать
порог только по максимальному TNR нельзя.

Скрипт `calibrate_refusal.py`:

1. случайно выбирает часть `vehicle_id` как open-set;
2. удаляет их из gallery;
3. получает top-1 raw cosine для known/unknown query;
4. выбирает максимальный TNR при заданном минимальном recall.

Запуск на holdout:

```bash
python research/calibrate_refusal.py \
  --embeddings artifacts/embeddings.npy \
  --index artifacts/embeddings_index.csv \
  --ground-truth /path/to/test_ground_truth.csv \
  --target-recall 0.70 \
  --json research/results/refusal_calibration.json
```

`--cross-camera` нужен только для сравнения с ranking-протоколом жюри. Для
порогa сервиса без `camera_id` используйте запуск без этого флага.

Результат остаётся диагностическим: выбранный порог нельзя считать финальным,
пока он не проверен на чистой выборке организаторов и на нескольких seed.

## Дополнение (honest-eval, 17.10): «чистый» режим, 5 фолдов, метрики эталона

Чего не было выше и что добавляет `research/calibrate_refusal_folds.py`:

- **распределение** — режим «без почти-дублей» (`nodup` в `research/honest_eval.py`):
  из галереи убраны все кадры той же машины с той же камеры, что у запроса,
  в том числе для отказа. Верный кандидат — только с другой камеры; это ближе
  всего к «чистой» выборке экспертов;
- **галерея** — big из honest_eval: все 150 машин holdout + весь тест как чужие
  машины (2.2k кадров), 25 % машин фолда без пары;
- **метрики эталона**: TP = принят **и** верхний кандидат верный. У
  `calibrate_refusal.py` recall — доля принятых запросов с парой, даже если
  top-1 неверный; на кросс-камерных top-1 это завышает;
- **калибровка вне фолда**: порог выбирается на одном фолде (правило то же —
  максимум TNR при recall ≥ цели) и проверяется на остальных четырёх; повтор
  для каждого из 5 фолдов даёт разброс и порога, и метрик (ddof=1).

```bash
python research/calibrate_refusal_folds.py --data-dir <данные> [--env REID_WEIGHTS=...] \
  [--fixed "имя=порог"] --out research/honest_eval_results/refusal_folds.json
```

Для сравнения — тот же отбор в режиме с почти-дублями (как в сервисе на
сдаточном тесте): recall ≥ 0.6 → порог 0.953 ± 0.011 (TNR 1.000), recall ≥ 0.7 →
0.930 ± 0.012 (TNR 0.995). Пороги двух режимов не пересекаются: порог
нужно калибровать на том распределении, где его применяют.

Выводы:

- при 0.8025 на «чистых» данных recall всего 0.34; порог 0.8743 из отчёта даёт
  0.10 — тот самый «recall < 10 %»;
- рабочая точка с recall ≥ 0.7 на чистых данных стоит TNR ≈ 0.62; с recall ≥ 0.6 —
  TNR ≈ 0.73. Это компромисс модели, а не порога: лучше разделения на этом
  скоре нет;
- разброс порога между фолдами ±0.04 при 30 машинах в фолде — порог
  устойчив до второго знака, метрики — до ±0.13 по recall; для защиты
  называть порог 0.69–0.73 и интервал метрик, а не одну цифру;
- пороги из этой таблицы — для модели студента; новую модель калибровать тем
  же скриптом с `--env REID_WEIGHTS=...`.
