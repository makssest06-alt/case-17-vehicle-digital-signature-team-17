# Сценарий демонстрации

Пошагово: что открываем, что нажимаем, что говорим. Четыре запроса
подобраны заранее и прогнаны через живой сервис — файл
`research/results/demo_verified.json` содержит ответ сервиса на каждый.

**Перед показом.** Поднять стенд и один раз прогреть модель, иначе первый
запрос займёт лишние секунды на загрузку весов:

```bash
cp .env.example .env && docker compose up -d
curl -s localhost:8000/health                 # ждём status: ok
python research/verify_demo.py                # все четыре случая ещё живы
```

Кадры для демонстрации лежат в `/opt/case17/data/crops/train/`, имена —
в таблицах ниже. Их удобно заранее скопировать на рабочий стол,
чтобы не искать во время показа.

## Шаг 1. Лёгкий случай: машина найдена уверенно

**Зачем.** Показываем, что базовый сценарий работает и выглядит понятно.

| | |
|---|---|
| Файл кадра | `4b90daade9334addb76bf838887e1430.jpg` |
| Машина | 904 |
| Яркость кадра | 136.7 из 255 |
| Рамка | вся картинка: x=0, y=0, w и h по размеру кропа |
| Ответ сервиса | правильная машина на месте **1**, уверенность **0.9686** |
| Время ответа | 676.2 мс |
| Объяснение | карта 14×14 за 1058.2 мс |
| Скриншот | `pitch_assets/09_ui_search.png` |

**Что сказать.** Оператор загрузил кадр, обвёл машину, нажал «найти». Первый кандидат — та же машина с другой камеры. Второй кандидат — тоже она, другим кадром. Уверенность видна числом, а не «похоже, подходит».

## Шаг 4. Запрос без пары: сервис отказывается отвечать

**Зачем.** Отказ — это 10% оценки и главное отличие продукта от ноутбука.

| | |
|---|---|
| Файл кадра | `ab0b9fb18f0c4c958af627794bd0bb88.jpg` |
| Машина | 1009 |
| Рамка | вся картинка: x=0, y=0, w и h по размеру кропа |
| Ответ сервиса | **отказ**: Уверенного совпадения нет: лучший кандидат 0.296 при пороге 0.511. |

**Что сказать.** Этой машины в галерее нет — мы убрали все её кадры заранее. Сервис не выдаёт «лучшее из плохого», а честно говорит, что уверенного совпадения нет, и называет число: лучший кандидат и порог. Порог не выдуман — это максимум индекса Юдена на рабочем распределении.

## Если спросят

**«А это не по номеру?»** — Нажимаем «показать почему» на любом кадре.
Зона номера в подсветке не участвует. В коде нет ни OCR, ни детектора
текста — это проверяется поиском по репозиторию за десять секунд.

**«Откуда порог?»** — Открываем `pitch_assets/05_refusal.png`: два
распределения максимального сходства, с парой в галерее и без пары.
Порог — максимум индекса Юдена: 0.5114, F1 0.934, полнота 0.939, TNR 0.927. Строгий режим: 0.6354, TNR 0.982.

**«Заработает ли на миллионе?»** — `research/ANN.md`: это замер, а не оценка.
HNSW отвечает за 0.41 мс против 137 мс точного перебора, теряя 0.26 mAP.

**«Почему галерея в демо маленькая?»** — В демо-галерее только размеченные
кадры отложенных машин, чтобы каждое «это та же машина» можно было
проверить по `vehicle_id` прямо на экране. На полной галерее сервис
работает так же, метрики — в `docs/SUBMISSION_README.md`.

## Чего на демонстрации не делаем

* Не загружаем случайные фото из интернета: галерея собрана из выборки
  заказчика, и совпадения там быть не должно — это выглядит как провал,
  хотя это правильный отказ.
* Не показываем первый запрос после подъёма контейнеров: он включает
  загрузку весов и вводит в заблуждение по времени.
* Не называем цифр, которых нет в `research/results/`.
