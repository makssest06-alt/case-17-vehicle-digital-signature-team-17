## Как считается F1 в режиме отказа

Как в эталоне организаторов (`research/official_evaluate.candidate_metrics`): решение принимается на уровне запроса, кандидат — top-1 по сырому косинусу, ответ даётся, если его оценка уверенности ≥ порога.

- **TP** — у запроса есть пара в галерее (кадр той же машины с другой камеры), ответ дан и top-1 верный;
- **FP** — ответ дан, но top-1 неверный, или пары у запроса нет вовсе;
- **FN** — пара есть, а сервис отказал; **TN** — пары нет, и сервис отказал.
- Precision = TP / (TP + FP), Recall = TP / (TP + FN), F1 = 2PR / (P + R); TNR = TN / (TN + FP без пары).
- Позитив F1 — «ответ дан и он верный». Принятый неверный top-1 у запроса с парой — FP, но не FN: отказ на таком запросе превращает FP в FN.
- PR-AUC — эталонный `pr_auc` по метке «у запроса есть пара»: «эталон» — отказанным ставится −inf (так эталон посчитает по `candidates.csv`), «без порога» — по всем top-1. mINP от порога не зависит.
- Протокол: 5 фолдов по 150 машинам holdout, 25 % машин фолда без пары, режим «без почти-дублей». Порог выбирается на 2.2k-записях одного фолда и проверяется на остальных четырёх — на 2.2k и без изменений на других галереях; ± — разброс по 5 повторам. 8996 — одна галерея состава GENERALIZATION_RESULTS.md: без пары в каждой проверке в среднем 5 запросов, TNR там почти не информативен.

## Выводы

- **F1 не держит ни одна оценка**: от 2.2k к 10.8k F1 падает на 0.10–0.20 у всех правил выбора, потому что падает само ранжирование (mINP 0.671 → 0.527); порог это не лечит.
- **TNR сырого косинуса проваливается**: при пороге 0.70 — 0.712 на 2.2k, 0.301 на 10.8k. С ростом галереи максимум похожести у запросов без пары растёт (максимум из большего числа чужих машин), и фиксированный порог их пропускает.
- **z100 держит TNR начиная с 2.2k**: 0.804 → 0.819 → 0.822 (правило «F1 при TNR ≥ 0.70»), окна s2..s20 и s2..s50 ведут себя так же. Но на маленьких галереях TNR у z100 ниже: 0.590 при 343 кадрах против 0.897 у сырого косинуса — фона из ближайших соседей там мало.
- **Цена z100 — F1 на больших галереях**: на 10.8k 0.474 против 0.549 у 0.70 (recall 0.361 против 0.739); на 2.2k F1 почти равны (0.636 против 0.660). По PR-AUC без порога z100 лучше и падает меньше: 0.899 → 0.847 против 0.890 → 0.743.
- **Почему z стабильнее по TNR.** У запроса без пары s1 — максимум из N похожестей на чужие машины. С ростом N весь хвост распределения сдвигается вверх, поэтому сырой s1 растёт. Отрыв максимума от ближайших 100 соседей в единицах их же разброса для хвостов типа Гумбеля от N почти не зависит: растут и s1, и фон. У запроса с парой s1 — похожесть на свою машину, она от N не зависит, а фон растёт, поэтому recall z100 с ростом галереи падает. Это и есть цена.
- **Рекомендация.** Решение сервиса оставить на сыром косинусе с порогом 0.70: на галереях 1–2 тыс. кадров (тест организаторов — 750 кадров галереи) он лучше по TNR при том же F1 (0.679 / 0.740 против 0.677 / 0.634 у z100 на 1093 кадрах). z100 — запасная оценка для галерей от ~9 тыс. кадров: порог 3.953 ± 0.286, в `candidates.csv` confidence = z100 (больше — увереннее, отказ — пустой список), считается по одному запросу из его top-100 без других запросов.
