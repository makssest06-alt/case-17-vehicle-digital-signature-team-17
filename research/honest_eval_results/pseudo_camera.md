# Псевдо-камеры (шаг 2)

```bash
python research/pseudo_camera.py --zip <dataset.zip> --data-dir <папка с train.csv, test_*.csv> \
  --out-dir research/honest_eval_results
```

Кадры читаются прямо из `dataset.zip` организаторов (11 416 кадров, все
1920×1080 — разрешение камеру не различает). Машина в кадре замазывается
(bbox + 10 % заливается средним цветом), дескриптор фона — глобальный вектор
предобученного resnet18 (timm, ImageNet). Проверено также: карта градиентов
уменьшенного кадра и их сумма — хуже (ARI ≤ 0.03), см. `pseudo_camera.json`,
`train_grid`.

## Эталон для проверки — настоящие `camera_id` train

В `train.csv` камера есть (96 камер), в `test_*.csv` — нет. Поэтому способ
подбирается и проверяется на train, а применяется к тесту.

| Способ | Результат на train |
|---|---|
| Агломеративная кластеризация (косинус, average, лучший порог 0.15) | 485 кластеров на 96 камер, ARI 0.414, NMI 0.707, чистота 0.679, полнота 0.431 — одна камера дробится на день, ночь, дождь |
| **Голосование 5 ближайших кадров train** (основной способ) | точность **86.5 %**, при согласии ≥ 4 из 5 соседей (72 % кадров) — **98.0 %** |

Точность голосования посчитана честно: для кадра train соседи берутся только
среди кадров **других машин** (leave-one-vehicle-out) — так же, как у тестового
кадра, для которого в train нет ни его машины, ни соседних кадров проезда.

| Косинус до ближайшего соседа | Точность |
|---|---:|
| 0.825–0.899 (нижние 10 %) | 49.5 % |
| 0.899–0.913 | 69.4 % |
| 0.913–0.928 | 88.2 % |
| 0.928–0.942 | 96.9 % |
| 0.942–0.986 (верхние 25 %) | 99.3 % |

Худшие камеры — редкие: cam34 (1 кадр), cam9 (5), cam8 (6), cam76 (7),
cam75 (10) — у других машин соседей с них просто нет.

**Насколько уверен.** Для 72 % кадров (согласие ≥ 4 из 5) — почти наверняка
(98 % на train). Для кадров с косинусом соседа ниже ~0.90 — не уверен (≈50–70 %).
`pseudo_camera.csv` хранит долю голосов и косинус, чтобы фильтровать по
уверенности.

## Главный вывод: сдаточный тест снят теми же камерами, что train

| Косинус до ближайшего кадра train | train (кадры других машин) | test |
|---|---:|---:|
| 1-й процентиль | 0.8688 | 0.8745 |
| 5-й процентиль | 0.8896 | 0.8905 |
| медиана | 0.9281 | 0.9273 |
| доля кадров с согласием ≥ 4 из 5 | 72.3 % | 71.8 % |

- Тестовых кадров ниже 1-го процентиля train — 11 из 1860 (при одинаковых
  распределениях ожидалось бы ≈ 19), ниже 5-го — 88 (≈ 93).
- Тестовые кадры получили 89 из 96 камер train.
- В совместной кластеризации 1816 из 1860 тестовых кадров попали в кластеры с
  кадрами train; 44 — в 24 кластера только из теста (глазами эти 44 не
  разбирал; при дроблении камер на 504 кластера такие одиночки ожидаемы).

Проверено глазами (листы в кэше, не в репозитории):
- 25 кластеров × 6 кадров: чистые кластеры одной камеры (cam89, 92, 23, 70,
  20, 59, 78, 27, 33, 13, 12, 28, 57) и смешанные — ночные мокрые сцены и
  кадры с крупной машиной (кластеры c35, c161, c281, c454);
- 24 тестовых кадра рядом с ближайшим кадром train: во всех — та же сцена
  (разметка, столбы, фасады).

Следствие для честной валидации: камеры test ⊂ камеры train. Модель, которая
опирается на фон камеры, на сдаточном тесте этим не наказывается. Если на
«чистой расширенной» выборке экспертов есть **другие** камеры, это отдельная
причина падения, которую на наших данных воспроизвести нельзя — только
оценить, насколько модель опирается на фон (шаг 7, разбор по псевдо-камере).

## Файлы

- `pseudo_camera.csv` — `image_id, split, pseudo_cam, vote_share, nn_cos, cluster`

- `pseudo_camera.json` — сетка порогов, метрики, сравнение test ↔ train.
