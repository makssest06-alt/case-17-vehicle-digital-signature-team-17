# Замер soup150s2 на арендованной A5000 (20.10.2026)

Железо близко к жюри (Q30: A5000 24 ГБ + 2× Xeon Gold 6338): RTX A5000 24 ГБ,
AMD Ryzen Threadripper PRO 3955WX (16 ядер / 32 потока, 4.4 ГГц), 100 ГБ RAM.
Прогон нативный (torch 2.5.1+cu124, python 3.12): на инстансе-контейнере LXC docker
не поднимается (нет прав на mount/iptables) — на числа это не влияет, замеряется
железо и код `extract()`, а не упаковка. Датасет — официальный `dataset.zip`.

Команда прогона (как в README, раздел 6):

```bash
REID_WEIGHTS=soup150s2.pt HF_HUB_OFFLINE=1 \
  python scripts/bench_extract.py --data /data --out bench_<вариант>.json
# варианты draft: EXTRACT_JPEG_DRAFT=1|2, потоки: EXTRACT_THREADS=4|16
```

| Вариант | latency_b1, мс (p95) | лучший FPS | баллы Q34, из 20 | детерминизм |
|---|---:|---:|---:|---|
| без draft, 4 потока (прежний дефолт) | 23.64 (26.46) | 86.2 | 17.25 | 0.0 |
| draft=2, 4 потока | 19.50 (23.57) | 141.4 | 20.0 | 0.0 |
| **draft=2, 32 потока (прод-дефолт)** | **19.11 (23.44)** | **157.6** | **20.0** | **0.0** |
| draft=2, 16 потоков | 19.52 (23.60) | 152.1 | 20.0 | 0.0 |
| контрольный повтор t16 вечером | 19.50 (23.99) | 156.9 | 20.0 | 0.0 |
| draft=1, 16 потоков | 19.34 (23.48) | 153.9 | 20.0 | 0.0 |

VRAM пик 2073 МБ, веса 1214 МБ (лимит 2 ГБ, Q37), загрузка весов ~4 с.

Выводы:

- Без draft гейт 100 FPS не берётся даже на 4.4-ГГц CPU: узкое место — декод JPEG
  в полном разрешении, а не GPU. Дополнительные потоки без draft не помогают
  (проверено ранее на 4060: 4 и 16 потоков дают одинаково — упор в forward).
- draft=2 решает с запасом 41–53 % над гейтом и даже улучшает latency
  (19.5 против 23.6 мс): половинный декод дешевле по всем стадиям.
- Цена — −0.003 raw / −0.005 DBA mAP@10 на holdout (extract_flags_soup150s2.md);
  на данных хакатона draft=1 и draft=2 дают одинаковые векторы (до 1/4 доходят
  6 кадров из 9556), в прод взят консервативный draft=2 (cap 1/2) — на случай
  крупных кадров в закрытом тесте.
- На момент замеров t4 и t16 draft жил только в пути `extract()` (`app/extractor.py`, разрешён Q36),
  сервис и офлайн-артефакты кропили полным декодом. С PR #20 кроп один на всё решение
  (`app/imaging.crop_frame`), пороги отказа и `artifacts/` пересчитаны под draft=2 —
  `recalibrate_soup150s2.json`: 0.8727 → 0.8881, строгий 0.9432 → 0.9445, правило рамок
  то же (так же вышло и в прогоне до исправления ключа кэша, `recalibrate_soup150s2_draft2.json`).
  Замер t32 снят уже на этом коде (`2379ed4`).
- Потоки подняты с 4 до 32 дефолтом: замер прод-конфига (draft=2, 32 потока) на том же
  стенде — 19.11 мс / 157.6 FPS, чуть выше t16 (152.1) в пределах шума; повторный прогон
  t16 тем вечером дал 156.9 FPS — воспроизводимость подтверждена. У жюри 64 ядра
  (2× Xeon Gold 6338) — запас по потокам есть; на качество потоки не влияют никак.

Файлы: `bench_default.json` (без draft), `bench_draft2_t4.json`,
`bench_draft2_t16.json`, `bench_draft2_t32.json` (прод-дефолт, замер 20.10 вечером,
тот же стенд и коммит 2379ed4), `bench_draft2_t16_check.json` (контрольный повтор),
`bench_draft_t16.json` (draft=1) + логи.
