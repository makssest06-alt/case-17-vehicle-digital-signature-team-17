# Дешёвый признак фона для штрафа за ту же камеру: a10

Веса `~/models/clean_student/clean_student_a10_ep28.pt`. Признак — пиксели кадра, который сервис и так декодирует: кадр 1920×1080 ужат до 128×72, машина (bbox + 10 %) выброшена маской. Правило штрафа то же, что в `bigallery_pp_a10.md`: τ — самый низкий порог с точностью «та же камера» ≥ 0.90 на парах обучающих машин, кандидат с той же камеры уходит в конец списка, поверх DBA k=1, галереи «как сервис». Ничего не подбиралось на галереях; признак для рекомендации выбран по калибровке и цене. Время — CPU этого Мака на запрос (декод кадра не входит: сервис его уже сделал; полный декод PIL — 5.6 мс, ужатие с маской — 0.89 мс). FPS — оценка: прогон a10 на RTX 4060 (8.27 мс на кадр при b1, 4.88 мс при b8, только модель) плюс это время последовательно.

Воспроизвести: `python research/cheap_bg.py --zip dataset.zip --data-dir <данные> --env REID_WEIGHTS=<веса> --tag a10`, затем `--report`.

## Вывод

- Выбран «градиенты 64×36 + гистограммы»: по калибровке на обучающих машинах — точность 0.92, полнота 0.30 против 0.93 / 0.29 у resnet18; 1.12 мс CPU на запрос против 18+ мс.
- Вклад штрафа поверх DBA k=1: F1 +0.129 / +0.118, TNR +0.080 / +0.091 на 9.0k / 10.8k (resnet18: F1 +0.108 / +0.095, TNR +0.064 / +0.075); mAP@10 +0.007 / +0.011 / +0.005. На 8996 без пары всего 7 запросов, её TNR не показатель.
- Как выбирался признак: условие «точность на отложенных группах камер ≥ 0.90» добавлено после первого прогона, когда таблицы калибровки и итога уже были видны; без него по полноте выбран бы «градиенты 32×18 + цвет + гистограммы» (точность 0.898). Вывод от выбора не зависит: F1 поверх DBA не ниже, чем с resnet18, на 9.0k и 10.8k у 7 дешёвых признаков из 7; F1 и TNR одновременно — у 1 (градиенты 64×36 + гистограммы). У остальных порог ушёл в сторону F1: TNR ниже, чем с resnet18.
- FPS: при b1 бюджет CPU на запрос для ≥ 100 FPS — 1.73 мс поверх 8.27 мс модели; выбранный признак — 1.12 мс → ≈ 106 FPS при b1, 167 при b8 (оценка; CPU сервера 4060 не мерили, CPU и GPU не перекрывали). Запас по CPU — в 1.5 раза: если CPU сервера медленнее Мака больше чем во столько раз, при b1 будет меньше 100 FPS; при b8 запас большой. Признак можно считать на CPU, пока GPU считает эмбеддинг, — тогда он не добавляет к задержке ничего, но это правка сервиса.
- Что нужно сервису (api/ — не трогал): при добавлении кадра в галерею хранить его фон (3328 float32 = 13.0 КБ на кадр, 10.8k кадров — 138 МБ), на запросе — фон запроса из уже декодированного кадра и косинусы с фоном top-100 кандидатов, порог τ из JSON.
