## Штраф за ту же камеру

- Сервис получает полный кадр и bbox (`/v1/search`, `/v1/gallery`: `image` + `x, y, w, h`, кроп делает сам `crop_with_pad`), так что фон доступен и для запроса, и для кадра галереи.
- «Та же камера» — косинус фоновых дескрипторов > τ. τ подобран по camera_id пар «кадр обучения — его top-100 по внешности» (300000 пар, той же камеры 10.8%), проверка по группам камер: τ по F1 0.877 — точность 0.57, полнота 0.49; τ с точностью ≥ 0.90 0.909 — 0.93 / 0.29. Детектор слабый: среди похожих машин фон соседних камер парковки неотличим, а τ по F1 вычитает и настоящие пары.
- Сетка λ (0.05, 0.1, 0.2, 0.3, исключить) — в JSON; на больших галереях ни одно λ не поднимает mAP@10, лучшее — без потерь (τ точн. ≥ 0.90).
- Эталон засчитывает top-1 той же машины с той же камеры как верный ответ у запроса с парой, поэтому штраф один снижает F1 (убирает «бесплатные» TP) и поднимает TNR; вместе с DBA F1 растёт.
- Дешёвый фон (`cheap_bg_a10.md`): пиксели уже декодированного кадра, ужатого до 128×72, машина выброшена маской. «градиенты 64×36 + гистограммы» — точность / полнота «та же камера» 0.92 / 0.30 (resnet18 0.93 / 0.29) за 1.12 мс CPU вместо 18+ мс.
## DBA

- Без почти-дублей соседи кадра галереи для каждого запроса берутся без его почти-дублей (иначе кадр той же машины с другой камеры впитывает почти-дубль запроса — обходной путь). Рост mAP@10 сохраняется и так: лучший k по mAP — dba k=1 на 9.0k, dba k=1 на 10.8k, dba k=1 на 8996; k ≥ 4 прироста не даёт (все k — в JSON).
- k выбран по тем же галереям, на которых мерится; защита — совпадение на трёх больших галереях и на 2.2k.

## Порог от размера галереи

- thr(N) = -0.064 + 0.2114·√(2 ln N): TNR держит около 0.70, но порог растёт до 0.847 и F1 на 10.8k падает до 0.288; z100 на тех же галереях лучше по обоим (0.474 / 0.822). Порог зависит не только от N: при той же N на смеси с кадрами обучающих машин он выше, чем на одном тесте (`threshold_vs_gallery_a10.md`).
- После постобработки Андрея: `python research/threshold_vs_gallery.py --data-dir <данные> --env REID_WEIGHTS=<веса> --score-fn <файл.py>:<функция> --tag <имя>`.

## Рекомендация

- **В прод — DBA k=1** по галерее (`research/dba.py`, как встроить — `HONEST_EVAL.md`): один пересчёт при старте и обновление при добавлении кадра, на запрос — ноль. Рост mAP@10 на всех больших галереях, в том числе без почти-дублей.
- **Штраф за ту же камеру — вместе с DBA и на дешёвом фоне** («градиенты 64×36 + гистограммы»): поверх DBA F1 +0.129 / +0.118 на 9.0k / 10.8k, +1.1 мс CPU, ≈ 106 FPS при b1 (оценка). Фон resnet18 не брать: пользы меньше (F1 +0.108 / +0.095) за 18+ мс CPU или ≈ 97 FPS на GPU. τ по F1 не брать: съедает настоящие пары.
- **Порог как функция N — не брать**: проигрывает z100. Финальный порог считать после постобработки Андрея тем же скриптом; на неизвестном размере закрытой выборки фиксированный порог держит F1, а TNR падает с ростом галереи — это ограничение фиксированного порога.
