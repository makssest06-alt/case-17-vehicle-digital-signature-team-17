## 0. Что проверялось

Заявления ветки:

1. постобработка (расширение запроса + CSLS + k-reciprocal) даёт большой прирост
   без переобучения;
2. кроп squash (вся машина, Resize без сохранения пропорций) лучше production
   Resize+CenterCrop;
3. ансамбль geom-squash 0.8 + ep29-base 0.2 даёт +7.96 mAP и лучше одиночной
   модели в 20/20 разбиений.

Проверка сделана с нуля: эмбеддинги пересчитаны из исходных кадров и чекпоинтов,
постобработка реализована заново (verify_team17.py) и сверена с
analysis/reid_postprocess.py. Ничего не взято из чужих .npy.

## 2. Спор о протоколе — разрешён

Код в репозитории (research/evaluate.py на ветках feat/prototype-skeleton,
feat/fast-inference, feat/research-baselines):

    keep = g_cam != q['camera_id']          # исключаем ту же камеру

Docstring: «Протокол как у жюри: ... кадры С ТОЙ ЖЕ камеры, что у query,
исключаются из выдачи».

Раздел 0 analysis/IMPROVEMENT_PLAN.md утверждает обратное — будто официальный
evaluate.py исключает «только junk-пары (тот же vehicle + та же камера)».
Это не соответствует коду. Их же VALIDATION_PROTOCOL.md говорит правильно:
«Same-camera пары исключаются из AP».

Ссылочный official_protocol.py в ветку не закоммичен (проверено git ls-tree),
как и прочие «файлы с экспериментами».

**Итог:** правильный протокол — исключение всей камеры запроса. Числа ветки,
полученные «junk-only», занижены примерно на 0.9 mAP относительно протокола из
репозитория.

## 5. Вердикт

Заявления ветки подтверждаются независимым воспроизведением:

* постобработка даёт основной прирост — подтверждено;
* squash лучше production-кропа Resize+CenterCrop — подтверждено;
* ансамбль двух моделей, каждая в своём режиме кропа (geom -> squash,
  ep29 -> base), лучше одиночной модели — подтверждено, 20/20 разбиений;
* итоговый прирост +7.3...+7.6 mAP (заявлено +7.96) и +6.9 Rank-1.

Расхождения:

1. Заголовок раздела 0 IMPROVEMENT_PLAN.md про протокол неверен: официальный
   протокол — исключение всей камеры, а не только junk-пар (см. раздел 2).
2. Абсолютные числа занижены примерно на 1 mAP относительно протокола из
   репозитория: geom ep30 = 76.74, а не 75.34.
3. official_protocol.py и прочие «файлы с экспериментами» в репозиторий не
   закоммичены — эта часть по коду невоспроизводима.
