Автор: Андрей. Всё измерено локально (RTX 3060 12 ГБ, i7-12700F), официальным
`evaluate.py` организаторов, на модели `clean_student_a10_ep28.pt`

Ничего из этого не встроено в сервис — это исследование и рекомендации.

## Главное в пяти строках

1. **Производительность — самый большой резерв баллов.** По FAQ (Q31/Q34) пропускная
   способность < 50 FPS даёт 0 из 10 %, ≥ 100 FPS — полные 10 %. Текущий путь извлечения
   признака на их Xeon 2 ГГц ≈ 46 FPS (ноль). Параллельная предобработка + нормировка на GPU +
   CUDA graph: **253 FPS против 62 на 3060, задержка 15.8 мс против 22.7, эмбеддинги побитно
   те же**. Оценка для A5000: 230–350 FPS → полные 20 %. Код — `perf/extractors.py`.
2. **Постобработку надо выбирать на галереях только из невиданных машин** (361 и 1111).
   Галереи с train-машинами (8996 / 9.0k / 10.8k) и 2.2k (с пачками почти-дублей тестовых
   запросов) завышают DBA и hubness в 5–10 раз.
3. **На 361 / 1111 пресет Ильи (DBA k=1 + фон + отказ) и hubness — ничья по mAP**, по отказу
   пресет лучше. Рекомендация: брать пресет Ильи.
4. **Отказ под формулу организаторов** (0.7·F1 + 0.3·TNR, 20 % open-set): флаг «та же сцена»
   даёт +0.18…0.20; оценка «сырой косинус лучшего кандидата без флага» стабильно лучше z100
   на 0.01–0.03.
5. **Модель:** восемь направлений не прошли порог +0.015 на обеих галереях. Единственный
   устойчивый плюс — дообучение на прямоугольном входе 224×320 (+0.012 / +0.018, R1 +0.02),
   но по заранее заданному правилу не принят.

## Протокол оценки

- Holdout как у организаторов: первый кадр каждой пары (машина, камера) → галерея,
  остальные → запросы. **546 запросов / 361 кадр галереи** (150 машин holdout, 5 байтовых
  дублей train↔holdout исключены).
- Галереи: **361** (только holdout) и **1111** (+ 750 кадров test gallery как чужие машины).
  9005 (+ train-машины) — только для справки.
- Ранжирование: top-10 строится до фильтра junk, junk вырезает evaluator (официальная семантика).
- Отказ «как сервис»: у open-set машины в галерее остаётся только кадр её же камеры.
  «Чистый» протокол: почти-дубли своей камеры скрыты. Порог выбирается вне фолда (2 фолда
  по машинам), ротации open-set.
- На 546 запросах разница < ~0.01 mAP — шум.

Потолок учёта камеры даже с настоящими `camera_id`: +0.008…+0.017; с псевдокамерами ≈ 0.
Нормировка эмбеддингов по средней камеры: −0.008…−0.033. Модель не запоминает пары камер:

### Отказ: 0.7·F1 + 0.3·TNR, 20 % open-set (`eval/refusal_objective.py`)

| Вариант, оценка | 361 как тест | 361 чистый | 1111 как тест | 1111 чистый |
|---|---:|---:|---:|---:|
| raw, без флага | 0.627 | 0.805 | 0.618 | 0.695 |
| DBA + фон, raw | **0.805** | 0.842 | 0.702 | 0.708 |

Правило дублей: косинус ≥ 0.94 или (≥ 0.85 и IoU рамок ≥ 0.70). Бесплатно по времени и почти

(−0.007 mAP). Пороги между фолдами плавают — брать из середины плато.

### Модель: что проверено и не прошло порог

Правило принятия (зафиксировано до прогона): ≥ +0.015 mAP@10 на 361 **и** 1111 с пресетом
Ильи, PR-AUC отказа не ниже чем на 0.01.

| Направление | 361 | 1111 | Итог |
|---|---:|---:|---|
| flip-TTA (`tta/`) | −0.000 | −0.007 | нет, ×2 GPU |
| bbox pad 0.15 / 0.05 | −0.013 / −0.001 | −0.013 / +0.002 | нет |
| переранжирование по патч-токенам (`local_rerank/`) | 0 / минус | 0 / минус | нет: AUC 0.85 против 0.97 у глобального |
| ансамбль A10 + старый студент (`ensemble/`) | −0.005…+0.000 | +0.011 | нет, ×2 цена |
| дообучение с майнингом похожих машин (`finetune/`, hm) | −0.003 | +0.009 | нет, майнинг = контролю |
| дообучение, контроль (ctrl, 6 эпох) | +0.001 | +0.010 | нет |
| усреднение весов A10/ctrl/hm (`soup/`) | ±0.002 | ≤ +0.008 | нет |
| **прямоугольный вход 224×320, дообучение** (`finetune/`, rect) | **+0.012** | **+0.018** | не прошёл на 361; R1 +0.020 на обеих |
| то же, α = 3 | +0.011 | +0.016 | нет |

Прямоугольный вход без дообучения хуже (−0.001 / −0.009), то есть эффект даёт именно
дообучение на новой форме. Стоимость: +40 % на прямой проход (94.6 против 67.5 мс на батч 32).
Самый перспективный кандидат, если команда решит рискнуть сменой модели — `rect_ep6`
(sha256 `612e9259…9c212ea97`, веса не в репозитории).

Закрытие зоны номера серым прямоугольником (контроль Q48) вредит не больше, чем такой же
прямоугольник сбоку (`eval/plate_occlusion.py`): за номер модель не держится.

## Что важно знать команде (из FAQ организаторов)

- Q31/Q34: формулы производительности выше; меряется полный цикл `extract()`, включая чтение
  файла и декодирование.
- Q15/Q17: отказ = 10 % × (0.7·F1 + 0.3·TNR); в закрытом тесте 20 % запросов без пары.
- Q38: другие запросы использовать нельзя (в сданном 27.09 `submission.csv` был `qq_expand`
  по `q @ q.T` — так больше нельзя). Галерея — статичная база: DBA, hubness, переранжирование
  внутри top-K одного запроса разрешены.
- Q2: `camera_id` и производные от него на инференсе запрещены — попарное сходство фона кадров
  из `camera_id` не выводится; голосование по train-кадрам с метками камер — выводится.
- Q39: при `docker build` сеть разрешена — веса A10 можно скачивать в Dockerfile по URL с
  проверкой sha256 (обход квоты LFS).
- Q48: финалистов проверяют на тесте с замазанным номером.

## Как запускать

Скрипты запускались из рабочей папки вне репозитория, пути к данным (`case17_data`),
весам (`Downloads`) и вспомогательным файлам заданы константами в начале файлов —
поправьте под себя. Внешние зависимости:

- копия `api/` (загрузчик сервиса) — ожидается в `../tta/api` относительно скриптов;
- код Ильи (`api/app/pp/`: `dba`, `background`, `rerank`) — ветка `ilya/pp-dba-camera`,
  ожидается в `../ilya_zip/api`;
- `pseudo_camera.csv` — `research/honest_eval_results/` ветки `ilya/honest-eval`;
- модули обучения (`backbones.py`, `head_model.py`, `train_reid.py`, `train_distill.py`) —
  `research/finals_handoff/training/` ветки `team17/finals-student-gpu-handoff`.

Веса, эмбеддинги и кэши (`.pt`, `.npz`) в репозиторий не кладутся.
