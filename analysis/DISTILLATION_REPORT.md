# Дистилляция ансамбля в одну модель — итог

Цель: получить **одну маленькую/быструю модель**, близкую по качеству к
4-модельному ансамблю (89.52 mAP@10 официально), но без его стоимости.

## Итог: победитель

**`siglip2_distill_ensemble_ep28.pt`** — один чекпоинт, SigLIP2 ViT-B/16 + голова,
обученный **дистилляцией** от ансамбля (учитель = ансамбль 4 моделей).

| Метрика | Значение |
|---|---|
| mAP@10 (официальный протокол, val) | **88.59** |
| Rank-1 / Rank-5 | 84.75 / 94.19 |
| Скорость (CPU 2 потока) | **170.6 мс/кадр → 5.86 FPS** |
| Веса | 362 МБ |
| RAM (пик) | ~795 МБ (влезает в `mem_limit 1536m`) |
| TTA | **не нужен** (учитель уже «вшил» усреднение с отражением) |

## Сравнение (всё на CPU, 2 потока; официальная mAP@10)

| SigLIP2 + TTA (одна) | 86.16 | 343.2 | 2.91 | 362 МБ | 796 МБ |
| **дистил. студент (no TTA)** | **88.59** | **170.6** | **5.86** | **362 МБ** | **795 МБ** |

| EfficientNet-B0 дистил. | 34.47 | 57.5 | 17.4 | ~20 МБ | — |

| *(справочно)* ансамбль 4 + TTA | 89.52 | ~1400 | ~0.7 | 1.74 ГБ | ~2.08 ГБ |

## Почему это лучший вариант

1. **Качество**: 88.59 — практически как тройка Андрея с TTA (88.84), но это
   **одна модель**, а не три, и **без TTA**.
2. **Скорость**: **5.86 FPS против 2.99 у production** — ровно **×1.96 быстрее**
   (за счёт отказа от TTA). Против ансамбля — в ~8 раз быстрее.
3. **Память**: 362 МБ весов, ~795 МБ RAM — **влезает в текущий лимит 1536m**
   без правок инфраструктуры.
4. **Простота**: один чекпоинт вместо 4, без кода фьюжна.

## Что такое дистилляция (как обучали)

Учитель — ансамбль 4 моделей; его эмбеддинги (L2-нормированные, взвешенные)
посчитаны на train-сплите (8644 кадра) и заморожены. Ученик (SigLIP2 ViT-B/16 +
голова, старт с чистых предобученных весов SigLIP2) обучается:

```
loss = ArcFace + batch-hard Triplet + alpha * (1 - cos(student_bn, teacher))
```

Рецепт тот же, что у squash-моделей Андрея (squash-кроп, геом- + фото-аугментации,
PK P=8 K=4 cross-camera, 30 эпох, RTX 4060, ~33 мин).

**Подбор alpha** (ключевой гиперпараметр — сила дистилляции):

| alpha | cos со учителем | mAP@10 (no TTA) |
|---:|---:|---:|
| 0 (обычное обучение) | — | ~85.9 |
| 2 | 0.23 | 86.88 |
| 6 | 0.47 | 87.55 |
| 12 | 0.60 | 88.07 |
| **25** | **0.67** | **88.40** |
| 50 | 0.70 | 88.11 |

Оптимум — **alpha≈25**: дальше растёт согласие с учителем, но падает
разнообразие/качество. Лучшая эпоха — **28**.

## Что проверено и отвергнуто

- **Маленькие бэкбоны** (MobileNetV3/EffNet-B0/ResNet18): дистилляция не спасает —
  17–34 mAP. Не хватает ёмкости. **DINOv2-S** — лучший из маленьких (74.78 при
  16.85 FPS), но −13.8 mAP к SigLIP2-студенту: слишком дорогая плата за скорость.
- **Понижение разрешения** SigLIP2-студента: 192 → 85.80 (−2.6), 160 → 81.79 (−6.6).
  Дороже, чем стоит.
- **TTA поверх студента**: +0.33 mAP за ×2 compute — невыгодно.
- **alpha > 25**: хуже (см. таблицу).

## Вывод

Единственный вариант, который выигрывает по **всем трём** критериям ТЗ
(качество 45%, скорость+память 20%, инженерия 15%) сразу — **дистиллированный
SigLIP2-студент**:

- качество: **+13.25 mAP** к production (88.59 vs 75.34);
- скорость: **×1.96** к production;
- память: влезает в текущий лимит без правок;
- инженерия: **один** чекпоинт вместо ансамбля.

Маленькие бэкбоны дают настоящий real-time (17–32 FPS), но теряют 14–70 mAP —
при весе качества 45% это заведомо убыточно.

## Воспроизведение

```bash
# 1) teacher-эмбеддинги ансамбля на train-сплите
python analysis/distill_teacher.py
# 2) обучение студента
python analysis/train_distill.py --backbone siglip2_base \
    --init-from siglip2_init.pt --teacher teacher_emb.npy \
    --rows-csv distill_train_rows.csv --tag siglip2_distill --alpha 25 --epochs 30 --amp
# 3) извлечение эмбеддингов (squash, БЕЗ TTA)
python analysis/extract_emb.py --ckpt models/siglip2_distill_ensemble_ep28.pt \
    --tag student --tf-mode squash
```
