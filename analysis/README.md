## Главное в трёх строках

1. **Модель видит только 66.6% длины машины.** Трансформ `Resize(248)+CenterCrop(224)`
   срезает перед и зад. Подача всей машины (squash) даёт **+2.9 mAP**.
2. **Постобработка эмбеддингов** (расширение запроса + CSLS + re-ranking) даёт
   **+3.1 mAP** и не требует переобучения.
3. **Обучение на squash с нуля** (30 эпох, 37 мин на RTX 3060) даёт 84.76 mAP —
   выше прежнего ансамбля. Согласованность кропа при обучении и инференсе
   оказалась важнее объёма данных.
4. **Ансамбль моделей**, каждая в своём нативном кропе, — ещё **+1.3 mAP**.
5. **Подбор параметров постобработки** под смесь (k1=30, alpha=3.0; проверено
   парно на 40 разбиениях: +0.79 ± 0.07, лучше в 39/40) — ещё **+0.66 mAP**.
6. **Замена бэкбона на SigLIP 2** — тот же рецепт и датасет, но **+3.4 mAP**
   в base-метрике. Самая дешёвая крупная правка: меняется одна строка в
   реестре бэкбонов. Лучшая одиночная модель проекта — **85.94 mAP**.
7. Вместе: **75.34 → 88.80 mAP**, Rank-1 **70.78 → 85.66** (официальный протокол).
   Подтверждено официальным `evaluate.py`: **0.8880 / 0.8566 / 0.9437**.

**Итоговая смесь — три модели:**

| Модель | Кроп | Вес |
|---|---|---:|
| `siglip2_scratch30_ep28` | squash | 0.45 |
| `sq_scratch30_ep26` | squash | 0.25 |
| `siglip_vitb16_reid_ep29` | base | 0.30 |

Прежняя geom-base-модель вытесняется в нулевой вес: полный перебор по
симплексу (1771 комбинация) даёт с ней то же, что и без неё.

**Тёплый старт не помогает, обучение с нуля — помогает.** Дообучение
geom-чекпоинта уводит модель от хорошего оптимума (80.0–80.6 против 81.40),
а полный прогон с нуля на squash-трансформе даёт 84.76. Прежний вывод
«обучение бесполезно» опирался на прогон, убитый на 5-й эпохе из 30.

**Проверять гипотезы только на независимых разбиениях.** Подбор и отчёт на
одних и тех же разбиениях систематически завышают результат. Пример из
работы: тюнер постобработки предложил отключить расширение запроса, и на
подгоночных зёрнах это выглядело выигрышем, но на зёрнах 100–139 разницы
не оказалось вовсе (87.98 против 87.98) — правку отклонили. А смена CSLS
k 10→5 на тех же независимых разбиениях подтвердилась парно
(+0.64 ± 0.39, лучше в 39/40) и была принята.

## Как проверить

```bash
# 1. посчитать эмбеддинги трёх моделей (query и gallery)
#    siglip2-squash и sq30-squash (обучены нами), ep29-base
# 2. прогнать постобработку
python reid_postprocess.py \
    --query emb_siglip2_ep28_qry.npy --gallery emb_siglip2_ep28_gal.npy \
    --query-ids q_ids.txt --gallery-ids g_ids.txt \
    --query-extra emb_ep29_base_qry.npy --gallery-extra emb_ep29_base_gal.npy \
    --query-extra emb_sq30_ep26_qry.npy --gallery-extra emb_sq30_ep26_gal.npy \
    --out submission.csv --candidates candidates.csv
```

Веса 0.45 / 0.25 / 0.30 — это и есть лучшая конфигурация (задаются
`--ensemble-weight`). Параметры постобработки (`--qq-alpha 3.0`,
`--rerank-k1 30`, CSLS k=5) уже стоят значениями по умолчанию.

Зависимости: только `numpy`.

## Важная поправка к метрикам

Мы считали метрики, исключая **всю** камеру запроса. Официальный `evaluate.py`
исключает только junk-пары (тот же vehicle_id **И** та же camera_id). Наши числа
завышены примерно на 1 mAP:

| Модель | Наш протокол | Официальный |
|---|---:|---:|
| ep29 | 74.32 | 73.16 |
| geom ep30 | 76.34 | 75.34 |

## Воспроизводимость обучения

Скрипт geom-обучения в репозиторий заложен не был (в `d108d59` только веса и
README). **Рецепт восстановлен из самого чекпоинта**: внутри `.pt` лежит ключ
`args` с полным набором параметров прогона, а в `encoder.*` — полный
`state_dict` энкодера timm (162 из 162 тензоров, `strict=True`). Поэтому веса
не нужно качать из HuggingFace — обучение полностью офлайновое.

```
backbone=siglip_base  out_dim=512  hidden=1024  dropout=0.3  loss=arcface
epochs=30  lr_head=3e-4  lr_backbone=1e-5  wd=5e-4  P=8  K=4  warmup=3
amp=true  seed=42  context=0.10  geom_aug=true  tag=siglip_geom_pad10
```

Скрипт — `analysis/train_reid.py`.
