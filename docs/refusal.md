# Режим отказа

Итоговая схема (команда, 18.10): **ранжирование — DBA k=1 + штраф по фону; отказ — z100 по кандидатам без почти-дублей, где почти-дубль = фон ИЛИ правило рамок**. Правило рамок в ранжирование не идёт: оно задевает 0.9 % настоящих пар. Все числа — на галереях 361 и 1111 из невиданных машин, как в закрытом тесте (`research/honest_eval_results/closed_gallery_a10.md`).

## Что считается отказом

- `/v1/search` отвечает `refusal: true` (`low_similarity`), если оценка уверенности меньше порога, и `gallery_empty`, если галерея пуста. Иначе — кандидаты.
- Метрика эталона (`candidate_metrics`): у запроса без пары отказ — TN, ответ — FP; у запроса с парой ответ с верной машиной на первом месте — TP, с чужой — FP, отказ — FN. PR-AUC — площадь под кривой точность–полнота оценки для «у запроса есть пара», от порога не зависит.

## Оценка уверенности

- `z100` = (s1 − mean(s2..s100)) / std(s2..s100) по кандидатам top-100 (по DBA-скору) без почти-дублей.
- Почти-дубль для отказа: косинус фонов > 0.68127 **или** правило рамок — сырой косинус ≥ 0.84 и IoU рамок ≥ 0.6, сдвиг центра ≤ 0.3 размера рамки. Пороги рамок Андрея (≥ 0.94, или ≥ 0.85 и IoU ≥ 0.7) почти равны нашим: F1 / TNR 0.827 / 0.741 на 361 и 0.668 / 0.719 на 1111 против наших 0.834 / 0.726 и 0.683 / 0.715 — у наших выше средний F1.
- Где в конфиге: `api/app/config.py` — `REFUSAL_SCORE`, `SEARCH_THRESHOLD`, `SEARCH_THRESHOLD_STRICT`, `PP_DEDUP_RANK`, `PP_DEDUP_REFUSAL`; посчитанные пороги — `REFUSAL_PRESETS`.

## Как выбран порог

- Протокол Андрея: 546 запросов / 361 кадр holdout; 1111 = 361 + 750 кадров test gallery как чужие машины. Отказ «как сервис»: 4 ротации по 25 % машин — у них в галерее остаётся кадр одной камеры, запросы с этой камеры без пары, но с почти-дублем.
- Порог вне фолда (2 фолда по машинам): на фолде выбора — TNR ≥ 0.70 на 361 **и** на 1111, из таких — максимум среднего F1; в конфиг — медиана по фолдам × ротациям, проверка — на отложенных фолдах с ней. Пороги по фолдам: 4.66, 4.54, 5.28, 4.64, 4.63, 4.47, 5.84, 5.03 — плато шириной ~1, берём середину.
- 2.2k, 9.0k, 10.8k для выбора не годятся: в 2.2k пачки почти-дублей тестовых запросов, в 9.0k/10.8k — кадры обучающих машин; обе завышают DBA (на 2.2k +0.060 mAP@10, на 1111 +0.009).

## Сколько F1 отдаём за TNR

| Галерея | Сейчас без постобработки: raw 0.8025 | Итог, F1-оптимум без ограничения (порог 3.42) | **Итог, порог 4.65 (F1 при TNR ≥ 0.70)** |
|---|---:|---:|---:|
| 361 | 0.843 / 0.077 | 0.881 / 0.361 | **0.834 / 0.726** |
| 1111 | 0.841 / 0.077 | 0.760 / 0.308 | **0.683 / 0.715** |

Значения — F1 / TNR. Без постобработки запросу без пары отвечает кадр его же машины с той же камеры, поэтому TNR низкий.

## Запасной план без фона (если FPS с фоном не пройдёт)

Ранжирование — DBA k=1, отказ — z100 без почти-дублей по правилу рамок (`PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=bbox`), порог 4.9039: F1 / TNR 0.825 / 0.723 на 361 и 0.687 / 0.740 на 1111, mAP@10 0.8854 / 0.7489 (с фоном 0.8855 / 0.7511). Признак фона на этих галереях даёт мало; правило рамок стоит 0.04 мс на запрос против 1.4 мс у фона.

## Воспроизвести

```bash
python research/closed_gallery.py --data-dir <данные> --env REID_WEIGHTS=<веса a10> --tag a10 --zip dataset.zip
```

Пишет `closed_gallery_a10.json` / `.md` и этот файл; пороги для `REFUSAL_PRESETS` — в JSON, ключ `config_presets`. Около минуты на готовых эмбеддингах.

## Оговорки

- 150 машин holdout: на фолд ~37 запросов без пары, шаг TNR ~0.03; разброс порогов по фолдам ~1 единица z.
- Эмбеддинги — из готовых JPEG-кропов; у Андрея свой кэш, числа сходятся до 0.003 mAP@10.
- Предположение протокола: в закрытой галерее у запроса без пары есть кадр его машины с той же камеры.
