# Режим отказа

Схема по умолчанию (команда, 20.10): **ранжирование — DBA k=1 без флагов; отказ — сырой косинус (raw) лучшего кандидата по DBA-галерее, без исключения почти-дублей** (`REFUSAL_SCORE=raw`, `PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=off`), **порог 0.8737** (строгий 0.9351). Запасной пресет — итог 18.10: отказ без почти-дублей «фон ИЛИ правило рамок» (`PP_DEDUP_REFUSAL=both`), порог 0.8249 (строгий 0.9356); почему его сменили — раздел «Почему отказ без исключения почти-дублей». z100 — пресет по выбору (`REFUSAL_SCORE=z100`, порог 4.3203, строгий 7.7994).

## Правило выбора порога — оценка организаторов

Источник — таблица ответов организаторов «Вопросы и ответы Бизнес 7. Фалькон Тех», лист «Объединённые вопросы участников»; номера — оттуда.

- Балл за режим кандидатов — **10 % × (0.7·F1 + 0.3·TNR)** (Q14, Q15). F1 и TNR — micro по запросам, по суммарной матрице ошибок (Q25); решение по запросу — верхний кандидат по confidence (Q19, Q23); TNR = TN / (TN + FP) только по запросам без пары (Q19). Отказ — нет строк query в `candidates.csv` (Q18, Q20); confidence — любая шкала, монотонная по уверенности (Q20, Q26).
- В закрытом тесте у **20 % query соответствующего ТС в gallery нет**, у остальных 80 % гарантирован хотя бы один кросс-камерный позитив; калибровать порог — на своём val-сплите из `train.csv` с ~20 % отложенных ID без пары (Q17, Q6).
- Порог — максимум среднего 0.7·F1 + 0.3·TNR по галереям 361 и 1111, вне фолда; в конфиг — медиана по фолдам × ротациям. Без пары в протоколе 20.0 % запросов.
- **Данные теста при подборе порога не использовались**: ни кадры, ни метки. Галереи — 361 кадр holdout, 750 (+389 кадров обучающих машин) и 1111 (+750 кадров обучающих машин); для запасного пресета порог фона τ = 0.68062 и правило рамок подобраны на парах обучающих машин (`research/honest_eval_results/cheap_bg_a10.md`, `dedup_compare_a10.md`).

## Почему отказ без исключения почти-дублей

На протоколе Q17 «DBA» выше прежнего итога: 0.7·F1 + 0.3·TNR 0.946 / 0.899 против 0.883 / 0.796 на 361 / 1111. Три трактовки кадра своей камеры на первом месте ответа (`research/refusal_topcam.py`) для этой модели не пересчитывались.

Прежний итог выигрывает только в сценарии Q22 — у запроса без пары в галерее остался кадр его машины с той же камеры (протокол q15, `closed_gallery_a10_q15.md` — посчитано на clean_student_a10_ep28, для этой модели не пересчитывалось): 0.824 / 0.717 против 0.603 / 0.589 у «DBA» на 361 / 1111. По ответу Q22 такой запрос («единственный позитив в gallery оказался junk (та же камера)») исключается из mAP и оценивается только как отказ. В закрытом тесте его нет: по ответу Q17 у 20 % query «соответствующего ТС в gallery» нет совсем, а у остальных 80 % «гарантирован как минимум один кросс-камерный позитив». Поэтому основной протокол — q17, а прежний итог оставлен запасным пресетом (`PP_DEDUP_REFUSAL=both`, `SEARCH_THRESHOLD=0.8249`, `SEARCH_THRESHOLD_STRICT=0.9356`) — на случай, если организаторы уточнят, что такие запросы в закрытой галерее есть.

## Почему raw, а не z100

- **На протоколе по Q17 у «DBA» raw выше z100**: 0.946 / 0.899 против 0.877 / 0.701 на 361 / 1111.
- **Раньше z100 выбрали на прежнем протоколе** (до 18.10): 4 ротации, правило «F1 при TNR ≥ 0.70», большая галерея — 361 + 750 кадров test gallery. Там порог raw, выбранный на 361, на 1111 давал TNR 0.459 против 0.687 у z100 (`closed_gallery_a10.md`).
- **Перенос порога между галереями** (сравнение сделано на итоге 18.10): официальная формула лучше у raw и с порогом, выбранным по своей галерее, и при переносе в обе стороны (таблица: строка — откуда взят порог, столбцы — где проверен).
- **Отвлекатели — обучающие машины**: модель их видела, они сильнее отвлекают, чем невиданные машины закрытого теста, поэтому TNR на 1111 скорее занижен (раздел «Почему на 1111 TNR ниже»).

## Что считается отказом

- `/v1/search` отвечает `refusal: true` (`low_similarity`), если оценка уверенности меньше порога, и `gallery_empty`, если галерея пуста. Иначе — кандидаты.
- Метрика `research/official_evaluate.py` (`candidate_metrics`): у запроса без пары отказ — TN, ответ — FP; у запроса с парой ответ с верной машиной на первом месте — TP, с чужой — FP, отказ — FN. Полнота — TP / (TP + FN). PR-AUC — площадь под кривой точность–полнота оценки для «у запроса есть пара», от порога не зависит.

## Оценка уверенности

- `raw` — косинус (по DBA-галерее) лучшего кандидата из top-100; в запасном пресете — лучшего без почти-дублей.
- `z100` = (s1 − mean(s2..s100)) / std(s2..s100) по тем же кандидатам.
- Почти-дубль (запасной пресет): косинус фонов > 0.68062 **или** правило рамок — сырой косинус ≥ 0.83 и IoU рамок ≥ 0.6, сдвиг центра ≤ 0.3 размера рамки, |log| отношения сторон ≤ 0.3. С порогами рамок Андрея (≥ 0.94, или ≥ 0.85 и IoU ≥ 0.7) — 0.840 / 0.949 / 0.735 / 0.873 на 361 и 0.839 / 0.696 / 0.783 / 0.796 на 1111 (F1 / TNR / полнота / оценка).
- Где в конфиге: `api/app/config.py` — `REFUSAL_SCORE`, `SEARCH_THRESHOLD`, `SEARCH_THRESHOLD_STRICT`, `PP_DEDUP_RANK`, `PP_DEDUP_REFUSAL`; посчитанные пороги обеих оценок — `REFUSAL_PRESETS`.

## Как выбран порог

- Протокол Андрея (`research/local_postprocess/experiments_2026-10-17/eval/head_to_head.py` в ветке `andrew-postprocess-throughput`; в этой ветке его повторяет `research/closed_gallery.py`): 546 запросов / 361 кадр holdout (первый кадр каждой пары машина-камера → галерея); 1111 — 361 + 750 кадров обучающих машин: первый кадр пары машина-камера, 750 пар случайно (сид 2026), без кадров из групп побайтных дублей полных кадров (`leak_audit.json`); 750 — 361 + 389 из тех же 750. Машин из запросов среди отвлекателей нет.
- Без пары — как в Q17: 5 ротаций, в каждой у 1/5 машин в галерее не остаётся ни одного кадра. Без пары 20.0 % запросов.
- Порог вне фолда (2 фолда по машинам): на фолде выбора — максимум среднего 0.7·F1 + 0.3·TNR на 361 и 1111; в конфиг — медиана 10 порогов (фолды × ротации), проверка — на отложенных фолдах с ней. Пороги по фолдам: 0.874, 0.873, 0.864, 0.862, 0.888, 0.890, 0.848, 0.880, 0.871, 0.875. Строгий — наименьший с TNR ≥ 0.98 на обеих на фолде выбора, медиана.

## Почему на 1111 TNR ниже

Отвлекатели — машины, которые модель видела при обучении. У запроса без пары лучший кандидат оценки отказа — такой кадр в 84 % случаев, его средний скор 0.740 против 0.525 на 361: обученные машины — сильные отвлекатели, отказов меньше (TNR 0.856 против 0.975).
