# Режим отказа

Итоговая схема (команда, 18.10): **ранжирование — DBA k=1 без флагов; отказ — z100 по кандидатам без почти-дублей, где почти-дубль = фон ИЛИ правило рамок** (`PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=both`), **порог 4.3475** (строгий 8.8469). Правило рамок в ранжирование не идёт: оно задевает 0.9 % настоящих пар; фон не идёт — см. «Кадр той же камеры в top-1».

## Правило выбора порога — оценка организаторов

Источник — таблица ответов организаторов «Вопросы и ответы Бизнес 7. Фалькон Тех», лист «Объединённые вопросы участников»; номера — оттуда.

- Балл за режим кандидатов — **10 % × (0.7·F1 + 0.3·TNR)** (Q14, Q15). F1 и TNR — micro по запросам, по суммарной матрице ошибок (Q25); решение по запросу — верхний кандидат по confidence (Q19, Q23); TNR = TN / (TN + FP) только по запросам без пары (Q19). Отказ — нет строк query в `candidates.csv` (Q18, Q20); confidence — любая шкала, монотонная по уверенности (Q20, Q26).
- В закрытом тесте у **20 % query соответствующего ТС в gallery нет**; калибровать порог — на своём val-сплите из `train.csv` с ~20 % отложенных ID без пары (Q17, Q6).
- Порог — максимум среднего 0.7·F1 + 0.3·TNR по двум галереям, вне фолда; в конфиг — медиана по фолдам × ротациям. Без пары в протоколе 20.0 % запросов.
- **Данные теста при подборе порога не использовались**: ни кадры, ни метки. Галереи — 361 кадр holdout и 1111 (+750 кадров обучающих машин); порог фона τ = 0.68127 и правило рамок подобраны на парах обучающих машин (`research/honest_eval_results/cheap_bg_a10.md`, `dedup_compare_a10.md`).

## Что считается отказом

- `/v1/search` отвечает `refusal: true` (`low_similarity`), если оценка уверенности меньше порога, и `gallery_empty`, если галерея пуста. Иначе — кандидаты.
- Метрика эталона (`candidate_metrics`): у запроса без пары отказ — TN, ответ — FP; у запроса с парой ответ с верной машиной на первом месте — TP, с чужой — FP, отказ — FN. Полнота — TP / (TP + FN). PR-AUC — площадь под кривой точность–полнота оценки для «у запроса есть пара», от порога не зависит.

## Кадр той же камеры в top-1 считается верным

В эталоне (`research/official_evaluate.py`, копия скрипта организаторов) кадр той же машины с той же камеры (junk) вычищается только из ранжирования: п. 1 протокола, `strip_junk` до усечения до 10 — поэтому он не влияет на mAP@10. В `candidate_metrics` его нет: «есть ли пара» считает `valid_positives` (та же машина с другой камеры), а верность ответа — строка 290:

```python
correct = gal_vid.get(top_gid, None) == row.vehicle_id
```

— только `vehicle_id`, камера не сверяется. У запроса с парой ответ кадром своей машины со своей камеры — TP. Штраф по фону в ранжировании (прежний итог) уводил такие кадры из top-1: их доля у запросов с парой 12 % / 12 % против 92 % / 91 % без штрафа (361 / 1111tr). Оценка отказа у обоих одна и та же, поэтому TNR совпадает, а F1 — нет:

| Ранжирование | mAP@10 361 / 1111tr | Порог | F1 / TNR / полнота / 0.7·F1+0.3·TNR 361 | то же 1111tr |
|---|---:|---:|---:|---:|
| DBA k=1 (итог) | 0.8854 / 0.7678 | 4.3475 | **0.882 / 0.747 / 0.840 / 0.842** | **0.754 / 0.476 / 0.689 / 0.671** |
| DBA k=1 + фон (прежний итог) | 0.8855 / 0.7677 | 4.3612 | 0.852 / 0.751 / 0.829 / 0.822 | 0.677 / 0.483 / 0.648 / 0.619 |

## Оценка уверенности

- `z100` = (s1 − mean(s2..s100)) / std(s2..s100) по кандидатам top-100 (по DBA-скору) без почти-дублей.
- Почти-дубль для отказа: косинус фонов > 0.68127 **или** правило рамок — сырой косинус ≥ 0.84 и IoU рамок ≥ 0.6, сдвиг центра ≤ 0.3 размера рамки. С порогами рамок Андрея (≥ 0.94, или ≥ 0.85 и IoU ≥ 0.7) — 0.881 / 0.751 / 0.837 / 0.842 на 361 и 0.753 / 0.479 / 0.686 / 0.671 на 1111tr (F1 / TNR / полнота / оценка).
- Где в конфиге: `api/app/config.py` — `REFUSAL_SCORE`, `SEARCH_THRESHOLD`, `SEARCH_THRESHOLD_STRICT`, `PP_DEDUP_RANK`, `PP_DEDUP_REFUSAL`; посчитанные пороги — `REFUSAL_PRESETS`.

## Почему z100, а не raw

raw — косинус лучшего кандидата без почти-дублей. Его порог зависит от размера галереи: чем больше чужих кадров, тем выше лучший косинус у запроса без пары. z100 меряет, насколько лучший выделяется среди ста ближайших, и переносится между размерами. Порог по тому же правилу; «361 → 1111tr» — выбран только по 361 и применён к обеим:

| Оценка | Порог выбран по | Порог | 0.7·F1+0.3·TNR 361 | 0.7·F1+0.3·TNR 1111tr | TNR 361 / 1111tr |
|---|---|---:|---:|---:|---:|
| z100 | 361 и 1111tr | 4.3475 | 0.842 | 0.671 | 0.747 / 0.476 |
| z100 | 361 → 1111tr | 4.5290 | 0.844 | 0.663 | 0.787 / 0.517 |
| z100 | 1111tr → 361 | 4.2648 | 0.841 | 0.667 | 0.726 / 0.437 |
| raw | 361 и 1111tr | 0.7586 | 0.881 | 0.756 | 0.876 / 0.575 |
| raw | 361 → 1111tr | 0.7142 | 0.882 | 0.724 | 0.830 / 0.441 |
| raw | 1111tr → 361 | 0.8078 | 0.849 | 0.768 | 0.911 / 0.704 |

Порог raw уезжает с размером галереи: 0.714 по 361 и 0.808 по 1111tr (z100 — 4.529 и 4.265); при переносе с 361 TNR на 1111tr у raw 0.441, у z100 0.517.

**Но по оценке организаторов raw на этом протоколе выше z100** — и по обеим галереям сразу (0.881 / 0.756 против 0.842 / 0.671), и при переносе порога с 361 (0.724 против 0.663 на 1111tr). z100 выбран на прежнем протоколе, где большая галерея была из кадров test gallery и порог raw при переносе терял TNR сильнее (`closed_gallery_a10.md`). Оставлен z100 (решение команды); переход на raw — открытый вопрос.

## Как выбран порог

- Протокол Андрея (`head_to_head.py`): 546 запросов / 361 кадр holdout (первый кадр каждой пары машина-камера → галерея); большая галерея — 361 + 750 кадров обучающих машин: первый кадр пары машина-камера, 750 пар случайно (сид 2026), без кадров из групп побайтных дублей полных кадров (`leak_audit.json`). Машин из запросов среди них нет.
- Без пары — как в Q17: 5 ротаций, в каждой у 1/5 машин в галерее не остаётся ни одного кадра — все их запросы без пары; каждая машина без пары в 1 ротации из 5. Без пары 20.0 % запросов.
- Порог вне фолда (2 фолда по машинам): на фолде выбора — максимум среднего 0.7·F1 + 0.3·TNR на 361 и 1111tr; в конфиг — медиана по 10 порогам (фолды × ротации), проверка — на отложенных фолдах с ней. Пороги по фолдам: 4.37, 4.33, 4.03, 4.37, 3.82, 4.38, 4.20, 4.35, 4.35, 5.06.

## С почти-дублем своей камеры (Q22)

У запроса без пары в галерее остаётся кадр его машины с той же камеры — почти-дубль, который отказ выбрасывает (протокол Андрея: 8 ротаций по 3/8 машин, `closed_gallery_a10_q15.md`). Порог по тому же правилу — 4.4320 (строгий 9.6690):

## Почему на 1111tr TNR ниже

Отвлекатели — машины, которые модель видела при обучении. У запроса без пары лучший кандидат оценки отказа (почти-дубли выброшены) — такой кадр в 81 % случаев, его средний скор 0.719 против 0.538 на 361: обученные машины — сильные отвлекатели, z100 у запроса без пары выше, отказов меньше (TNR 0.476 против 0.747). В закрытом тесте отвлекатели — невиданные машины; эта галерея, вероятно, строже к TNR, чем закрытый тест.

## Запасной план без фона вообще (если FPS с фоном не пройдёт)

Ранжирование то же — DBA k=1, отказ — z100 без почти-дублей только по правилу рамок (`PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=bbox`, `PP_CAMERA_PENALTY=off`), порог 4.3542 (строгий 8.8363): 0.882 / 0.748 / 0.839 / 0.842 на 361 и 0.754 / 0.469 / 0.688 / 0.668 на 1111tr против 0.882 / 0.747 / 0.840 / 0.842 и 0.754 / 0.476 / 0.689 / 0.671 у итога (F1 / TNR / полнота / оценка); mAP@10 0.8854 / 0.7678 — то же ранжирование. Правило рамок стоит 0.04 мс на запрос против 1.4 мс у фона.

## Оговорки

- 150 машин holdout: на фолд ~55 запросов без пары, шаг TNR ~0.02; разброс порогов по фолдам ~0.5–1 единица z.
- Отвлекатели большой галереи — обучающие машины (модель их видела), см. выше.
- Эмбеддинги — из готовых JPEG-кропов; у Андрея свой кэш, числа сходятся до 0.003 mAP@10.
- Закрытый тест: у запроса без пары машины в галерее нет (Q17) — основной протокол; запрос, у которого единственный позитив — кадр своей камеры (Q22), — раздел выше.
- Таблица ответов организаторов в репозитории не хранится; номера ответов — по ней.
