# Режим отказа

Итоговая схема (команда, 18.10): **ранжирование — DBA k=1 без флагов; отказ — z100 по кандидатам без почти-дублей, где почти-дубль = фон ИЛИ правило рамок** (`PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=both`), **порог 4.4320** (строгий 9.6690). Правило рамок в ранжирование не идёт: оно задевает 0.9 % настоящих пар; фон не идёт — см. «Кадр той же камеры в top-1».

## Правило выбора порога — оценка организаторов

- Режим отказа оценивается как **10 % × (0.7·F1 + 0.3·TNR)** — ответ организаторов Q15; в закрытом тесте **20 % запросов без пары** — Q17. Текст ответов — в таблице организаторов (ссылка и список тем — `research/finals_handoff/README.md`, раздел про ТЗ и ответы); формула Q15 — по пересказу команды (`research/local_postprocess/experiments_2026-10-17/README.md` ветки `andrew-postprocess-throughput`).
- Порог — максимум среднего 0.7·F1 + 0.3·TNR по двум галереям, вне фолда; в конфиг — медиана по фолдам × ротациям. Без пары в протоколе 20.0 % запросов.
- **Данные теста при подборе порога не использовались**: ни кадры, ни метки. Галереи — 361 кадр holdout и 1111 (+750 кадров обучающих машин); порог фона τ = 0.68127 и правило рамок подобраны на парах обучающих машин (`research/honest_eval_results/cheap_bg_a10.md`, `dedup_compare_a10.md`).

## Что считается отказом

- `/v1/search` отвечает `refusal: true` (`low_similarity`), если оценка уверенности меньше порога, и `gallery_empty`, если галерея пуста. Иначе — кандидаты.
- Метрика эталона (`candidate_metrics`): у запроса без пары отказ — TN, ответ — FP; у запроса с парой ответ с верной машиной на первом месте — TP, с чужой — FP, отказ — FN. Полнота — TP / (TP + FN). PR-AUC — площадь под кривой точность–полнота оценки для «у запроса есть пара», от порога не зависит.

## Кадр той же камеры в top-1 считается верным

В эталоне (`research/official_evaluate.py`, копия скрипта организаторов) кадр той же машины с той же камеры (junk) вычищается только из ранжирования: п. 1 протокола, `strip_junk` до усечения до 10 — поэтому он не влияет на mAP@10. В `candidate_metrics` его нет: «есть ли пара» считает `valid_positives` (та же машина с другой камеры), а верность ответа — строка 290:

```python
correct = gal_vid.get(top_gid, None) == row.vehicle_id
```

— только `vehicle_id`, камера не сверяется. У запроса с парой ответ кадром своей машины со своей камеры — TP. Штраф по фону в ранжировании (прежний итог) уводил такие кадры из top-1: их доля у запросов с парой 9 % / 10 % против 72 % / 71 % без штрафа (361 / 1111tr). Оценка отказа у обоих одна и та же, поэтому TNR совпадает, а F1 — нет:

| Ранжирование | mAP@10 361 / 1111tr | Порог | F1 / TNR / полнота / 0.7·F1+0.3·TNR 361 | то же 1111tr |
|---|---:|---:|---:|---:|
| DBA k=1 (итог) | 0.8854 / 0.7678 | 4.4320 | **0.864 / 0.668 / 0.833 / 0.805** | **0.723 / 0.424 / 0.669 / 0.634** |
| DBA k=1 + фон (прежний итог) | 0.8855 / 0.7677 | 4.4320 | 0.838 / 0.668 / 0.825 / 0.787 | 0.663 / 0.424 / 0.639 / 0.591 |

## Оценка уверенности

- `z100` = (s1 − mean(s2..s100)) / std(s2..s100) по кандидатам top-100 (по DBA-скору) без почти-дублей.
- Почти-дубль для отказа: косинус фонов > 0.68127 **или** правило рамок — сырой косинус ≥ 0.84 и IoU рамок ≥ 0.6, сдвиг центра ≤ 0.3 размера рамки. С порогами рамок Андрея (≥ 0.94, или ≥ 0.85 и IoU ≥ 0.7) — 0.864 / 0.656 / 0.835 / 0.801 на 361 и 0.724 / 0.416 / 0.672 / 0.632 на 1111tr (F1 / TNR / полнота / оценка).
- Где в конфиге: `api/app/config.py` — `REFUSAL_SCORE`, `SEARCH_THRESHOLD`, `SEARCH_THRESHOLD_STRICT`, `PP_DEDUP_RANK`, `PP_DEDUP_REFUSAL`; посчитанные пороги — `REFUSAL_PRESETS`.

## Почему z100, а не raw

raw — косинус лучшего кандидата без почти-дублей. Его порог зависит от размера галереи: чем больше чужих кадров, тем выше лучший косинус у запроса без пары. z100 меряет, насколько лучший выделяется среди ста ближайших, и переносится между размерами. Порог по тому же правилу; «361 → 1111tr» — выбран только по 361 и применён к обеим:

| Оценка | Порог выбран по | Порог | 0.7·F1+0.3·TNR 361 | 0.7·F1+0.3·TNR 1111tr | TNR 361 / 1111tr |
|---|---|---:|---:|---:|---:|
| z100 | 361 и 1111tr | 4.4320 | 0.805 | 0.634 | 0.668 / 0.424 |
| z100 | 361 → 1111tr | 4.5839 | 0.807 | 0.625 | 0.697 / 0.452 |
| z100 | 1111tr → 361 | 3.9847 | 0.783 | 0.644 | 0.547 / 0.325 |
| raw | 361 и 1111tr | 0.7760 | 0.824 | 0.717 | 0.801 / 0.559 |
| raw | 361 → 1111tr | 0.6879 | 0.830 | 0.671 | 0.700 / 0.321 |
| raw | 1111tr → 361 | 0.8210 | 0.808 | 0.727 | 0.864 / 0.682 |

Порог raw уезжает с размером галереи: 0.688 по 361 и 0.821 по 1111tr (z100 — 4.584 и 3.985); при переносе с 361 TNR на 1111tr у raw 0.321, у z100 0.452.

**Но по оценке организаторов raw на этом протоколе выше z100** — и по обеим галереям сразу (0.824 / 0.717 против 0.805 / 0.634), и при переносе порога с 361 (0.671 против 0.625 на 1111tr). z100 выбран на прежнем протоколе, где большая галерея была из кадров test gallery и порог raw при переносе терял TNR сильнее (`closed_gallery_a10.md`). Оставлен z100 (решение команды); переход на raw — открытый вопрос.

## Как выбран порог

- Протокол Андрея (`head_to_head.py`): 546 запросов / 361 кадр holdout (первый кадр каждой пары машина-камера → галерея); большая галерея — 361 + 750 кадров обучающих машин: первый кадр пары машина-камера, 750 пар случайно (сид 2026), без кадров из групп побайтных дублей полных кадров (`leak_audit.json`). Машин из запросов среди них нет.
- Отказ «как сервис»: 8 ротаций; в каждой у 3/8 машин в галерее остаётся кадр одной камеры (самой частой среди их запросов) — их запросы с этой камеры без пары, но с почти-дублем; каждая машина без пары в 3 ротациях из 8. Без пары 20.0 % запросов (у прежних 4 ротаций по 25 % машин — 13 %).
- Порог вне фолда (2 фолда по машинам): на фолде выбора — максимум среднего 0.7·F1 + 0.3·TNR на 361 и 1111tr; в конфиг — медиана по 16 порогам (фолды × ротации), проверка — на отложенных фолдах с ней. Пороги по фолдам: 4.31, 4.98, 3.94, 5.02, 4.26, 5.29, 4.24, 5.42, 4.27, 4.74, 4.24, 5.06, 4.19, 4.73, 4.24, 4.56.

## Почему на 1111tr TNR ниже

Отвлекатели — машины, которые модель видела при обучении. У запроса без пары лучший кандидат оценки отказа (почти-дубли выброшены) — такой кадр в 73 % случаев, его средний скор 0.738 против 0.575 на 361: обученные машины — сильные отвлекатели, z100 у запроса без пары выше, отказов меньше (TNR 0.424 против 0.668). В закрытом тесте отвлекатели — невиданные машины; эта галерея, вероятно, строже к TNR, чем закрытый тест.

## Запасной план без фона вообще (если FPS с фоном не пройдёт)

Ранжирование то же — DBA k=1, отказ — z100 без почти-дублей только по правилу рамок (`PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=bbox`, `PP_CAMERA_PENALTY=off`), порог 4.3930 (строгий 9.5405): 0.865 / 0.641 / 0.840 / 0.797 на 361 и 0.727 / 0.404 / 0.677 / 0.630 на 1111tr против 0.864 / 0.668 / 0.833 / 0.805 и 0.723 / 0.424 / 0.669 / 0.634 у итога (F1 / TNR / полнота / оценка); mAP@10 0.8854 / 0.7678 — то же ранжирование. Правило рамок стоит 0.04 мс на запрос против 1.4 мс у фона.

## Оговорки

- 150 машин holdout: на фолд ~55 запросов без пары, шаг TNR ~0.02; разброс порогов по фолдам ~1 единица z.
- Отвлекатели большой галереи — обучающие машины (модель их видела), см. выше.
- Эмбеддинги — из готовых JPEG-кропов; у Андрея свой кэш, числа сходятся до 0.003 mAP@10.
- Предположение протокола: в закрытой галерее у запроса без пары есть кадр его машины с той же камеры.
- Формула Q15 и доля Q17 — по пересказу команды; текст ответов организаторов в репозитории не хранится.
