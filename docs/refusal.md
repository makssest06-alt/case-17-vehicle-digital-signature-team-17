# Режим отказа

> **Предварительно.** Итог ниже посчитан для постобработки «DBA k=1 + оба (OR)», которую команда ещё не приняла (решение за Андреем). После решения пересчитать одной командой (раздел «Воспроизвести») и сменить одно число в `api/app/config.py`.

## Что считается отказом

- `/v1/search` отвечает `refusal: true` с `reason: low_similarity`, если оценка уверенности лучшего кандидата меньше порога, и `gallery_empty`, если галерея пуста. Иначе — кандидаты.
- В метрике эталона (`research/official_evaluate.py`, `candidate_metrics`): у запроса **без пары** (в галерее нет кадра его машины с другой камеры) отказ — TN, ответ — FP; у запроса **с парой** ответ с верной машиной на первом месте — TP, с чужой — FP, отказ — FN. TNR = TN / (TN + FP без пары), F1 — по TP, FP, FN. PR-AUC — площадь под кривой точность–полнота оценки уверенности для «у запроса есть пара», от порога не зависит. mAP@10 и mINP — качество ранжирования (mINP: доля позитивов до последнего позитива включительно).

## Какая оценка уверенности

- `raw` — косинус лучшего кандидата.
- `z100` = (s1 − mean(s2..s100)) / std(s2..s100): насколько лучший кандидат выделяется среди ста ближайших.
- С постобработкой обе считаются после DBA и штрафа, по кандидатам без флага «та же камера». Код — `api/app/pp/rerank.py`; исследование считает тем же кодом.
- Где в конфиге: блок «режим отказа» в `api/app/config.py` — `REFUSAL_SCORE` (формула) и `SEARCH_THRESHOLD` (+ `SEARCH_THRESHOLD_STRICT` для строгого режима). Посчитанные значения — `REFUSAL_PRESETS` там же. `docker-compose.yml` и `.env.example` своих чисел не держат.

## Как выбран порог

- **Протокол «как сервис»:** у запроса без пары в галерее остаётся кадр его машины с той же камеры — так выглядит галерея сервиса. 150 машин holdout, 5 фолдов по 30 машин (в обучение модели не входили), 25 % машин фолда — без пары.
- **Размеры галереи:** кадры holdout плюс случайная доля чужих кадров (весь тест и кадры обучающих машин), N от 361 до 10 847, и именованные 2.2k, 9.0k, 10.8k. Тест — только как чужие кадры, ничего на нём не подбирается.
- **Порог:** на фолде выбора — максимум F1 при TNR ≥ 0.70 по записям **всех размеров сразу** (размер закрытой выборки неизвестен), проверка — на остальных четырёх фолдах на каждом размере. Строгая точка — наименьший порог с TNR ≥ 0.98.
- **Формула:** выбирается правилом, записанным до прогона. Сначала оставить формулы, у которых при одном пороге TNR ≥ 0.70 на всех размерах, и из них взять ту, где больше средний F1. Если не прошла ни одна, взять ту, у которой больше минимальный TNR.

## Почему сырой порог зависит от размера галереи

- У запроса без пары лучший кандидат — самая похожая чужая машина, то есть максимум из N сходств. С ростом N он растёт: средний s1 у запросов без пары (DBA + фон OR рамка) — 0.560 при N = 361 и 0.761 при N = 10 847. Рост ложится на a + b·√(2 ln N), как у максимума N случайных величин с гауссовым хвостом.
- Лучший порог raw для каждого N отдельно растёт так же: 0.663 → 0.846. Один порог raw на все размеры (0.7866) даёт TNR 0.911 на малой галерее и 0.572 на 10.8k: чужие проходят.
- У z100 лучший порог от N почти не зависит (3.93–4.83): оценка меряет отрыв лучшего от фона, а фон растёт вместе с N.
- Без постобработки картина другая и хуже. Решает почти-дубль: у запроса без пары лучший кандидат — его же машина с той же камеры. Сервис сейчас (raw, порог 0.8025) на этом протоколе даёт TNR 0.062 на 2.2k и 0.048 на 10.8k при F1 0.809. F1 у него выше итогового только потому, что он почти не отказывает, а запросов с парой 75 %. Прежние 0.8025 / TNR 0.889 посчитаны без почти-дублей.

## Что делаем

- **Итог (предварительно): DBA k=1 + оба (OR), оценка `z100`, порог 4.1592 ± 0.2542 (по фолдам), строгий 7.3031.** TNR на размерах 0.635–0.890, F1 0.576–0.847. Правило TNR ≥ 0.70 на всех размерах при одном пороге не выполнила ни одна формула; z100 выбран по запасной ветке правила (больший минимум TNR).
- **Цена TNR.** F1-оптимум `z100` без ограничения на TNR — порог 3.3857: F1 / TNR 0.721 / 0.576 на 2.2k и 0.630 / 0.654 на 10.8k. С нашим порогом F1 меняется на -0.005 на 2.2k и -0.054 на 10.8k, TNR — на +0.303 и +0.236 (таблица ниже).
- **Альтернатива — raw с порогом от размера галереи:** thr(N) = 0.002 + 0.1997·√(2 ln N), где N — сколько кадров в галерее сервиса в момент запроса. Держит TNR 0.707–0.770 на всех размерах, но F1 на 10.8k 0.476 против 0.576 у `z100`. В сервисе не реализовано: нужно два числа, а не одно.
- **Другие исключения почти-дублей** (разбор — `dedup_compare_a10.md`), та же оценка `z100`: «DBA k=1 + штраф за ту же камеру» — порог 4.3501, F1 / TNR 0.691 / 0.824 на 2.2k и 0.555 / 0.862 на 10.8k; «DBA k=1 + правило Андрея (сходство + рамка)» — порог 4.2205, F1 / TNR 0.708 / 0.841 на 2.2k и 0.564 / 0.867 на 10.8k. Таблица ниже.
- **Порог не переносится между вариантами постобработки.** Включили её — смените `SEARCH_THRESHOLD` (и `STRICT`) на значение из `REFUSAL_PRESETS`. Иначе сервис предупредит в логе при старте.

## Воспроизвести

```bash
python research/refusal_mode.py --data-dir <данные> --env REID_WEIGHTS=<веса a10> --tag a10 --zip dataset.zip
```

Пишет `research/honest_eval_results/refusal_mode_a10.json` / `.md` (все таблицы, ± по фолдам) и этот файл. Значения для `REFUSAL_PRESETS` — в JSON, ключ `presets`. На готовых эмбеддингах — около минуты; первый прогон считает эмбеддинги моделью. Отдельный разбор «порог от N» — `research/threshold_vs_gallery.py --score service --mode neardup` (`threshold_vs_gallery_a10_service.md`).

## Оговорки

- 150 машин holdout × 5 фолдов. Запросов без пары около 146 на все фолды, шаг TNR — около 0.7 %. Разброс по фолдам — в JSON.
- Галерея команды 8996 не включена: в ней 7 запросов без пары, TNR там не показатель.
- Протокол «как сервис» предполагает, что в закрытой галерее есть кадры той же машины с той же камеры. Если их нет, картина ближе к режиму без почти-дублей (`honest_eval_a10_suite.md`), и порог надо брать оттуда.
- Штраф: τ = 0.68127 по camera_id обучающих машин, top-100 кандидатов, признак фона — `research/honest_eval_results/cheap_bg_a10.md`.
