# Режим отказа

Итоговая схема (команда, 18.10): **ранжирование — DBA k=1 без флагов; отказ — z100 по кандидатам без почти-дублей, где почти-дубль = фон ИЛИ правило рамок** (`PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=both`). Правило рамок в ранжирование не идёт: оно задевает 0.9 % настоящих пар; фон не идёт — см. «Кадр той же камеры в top-1». Все числа — на галереях 361 и 1111 из невиданных машин, как в закрытом тесте (`research/honest_eval_results/closed_gallery_a10.md`).

## Что считается отказом

- `/v1/search` отвечает `refusal: true` (`low_similarity`), если оценка уверенности меньше порога, и `gallery_empty`, если галерея пуста. Иначе — кандидаты.
- Метрика эталона (`candidate_metrics`): у запроса без пары отказ — TN, ответ — FP; у запроса с парой ответ с верной машиной на первом месте — TP, с чужой — FP, отказ — FN. PR-AUC — площадь под кривой точность–полнота оценки для «у запроса есть пара», от порога не зависит.

## Кадр той же камеры в top-1 считается верным

В эталоне (`research/official_evaluate.py`, копия скрипта организаторов) кадр той же машины с той же камеры (junk) вычищается только из ранжирования: п. 1 протокола, `strip_junk` до усечения до 10 — поэтому он не влияет на mAP@10. В `candidate_metrics` его нет: «есть ли пара» считает `valid_positives` (та же машина с другой камеры), а верность ответа — строка 290:

```python
correct = gal_vid.get(top_gid, None) == row.vehicle_id
```

— только `vehicle_id`, камера не сверяется. У запроса с парой ответ кадром своей машины со своей камеры — TP. Штраф по фону в ранжировании (прежний итог) уводил такие кадры из top-1: их доля у запросов с парой 10 % / 10 % против 80 % / 79 % без штрафа (361 / 1111). Оценка отказа у обоих одна и та же (почти-дубли «фон ИЛИ рамка» исключаются в ней в обоих), поэтому TNR совпадает, а F1 — нет:

| Ранжирование | mAP@10 361 / 1111 | Порог | F1 / TNR 361 | F1 / TNR 1111 |
|---|---:|---:|---:|---:|
| DBA k=1 (итог) | 0.8854 / 0.7489 | 4.6506 | **0.858 / 0.726** | **0.736 / 0.715** |
| DBA k=1 + фон (прежний итог) | 0.8855 / 0.7511 | 4.6506 | 0.834 / 0.726 | 0.683 / 0.715 |

Фон в ранжировании давал mAP@10 в пределах шума, а F1 отнимал. Выигрыш держится на предположении протокола: в закрытой галерее у запроса есть кадр его машины с его камеры (один кадр на пару машина–камера). Если такого кадра нет, разницы нет — в «чистом» протоколе Андрея (почти-дубли своей камеры скрыты) оба варианта совпадают (`research/honest_eval_results/refusal_formula_a10.md`).

## Оценка уверенности

- `z100` = (s1 − mean(s2..s100)) / std(s2..s100) по кандидатам top-100 (по DBA-скору) без почти-дублей.
- Почти-дубль для отказа: косинус фонов > 0.68127 **или** правило рамок — сырой косинус ≥ 0.84 и IoU рамок ≥ 0.6, сдвиг центра ≤ 0.3 размера рамки. Пороги рамок Андрея (≥ 0.94, или ≥ 0.85 и IoU ≥ 0.7) почти равны нашим: F1 / TNR 0.849 / 0.741 на 361 и 0.717 / 0.719 на 1111 против наших 0.858 / 0.726 и 0.736 / 0.715.
- Где в конфиге: `api/app/config.py` — `REFUSAL_SCORE`, `SEARCH_THRESHOLD`, `SEARCH_THRESHOLD_STRICT`, `PP_DEDUP_RANK`, `PP_DEDUP_REFUSAL`; посчитанные пороги — `REFUSAL_PRESETS`.

## Почему z100, а не raw

raw — косинус лучшего кандидата без почти-дублей. Его порог зависит от размера галереи: чем больше чужих кадров, тем выше лучший косинус у запроса без пары. z100 меряет, насколько лучший выделяется среди ста ближайших, и переносится между размерами. Порог по тому же правилу, что пресет; «361 → 1111» — выбран только по 361 и применён к обеим:

| Оценка | Порог выбран по | Порог | F1 / TNR 361 | F1 / TNR 1111 |
|---|---|---:|---:|---:|
| z100 | 361 и 1111 | 4.6506 | 0.858 / 0.726 | 0.736 / 0.715 |
| z100 | 361 → 1111 | 4.5378 | 0.868 / 0.713 | 0.756 / **0.687** |
| z100 | 1111 → 361 | 4.6022 | 0.862 / 0.720 | 0.744 / 0.701 |
| raw | 361 и 1111 | 0.7831 | 0.841 / 0.816 | 0.804 / 0.711 |
| raw | 361 → 1111 | 0.6589 | 0.914 / **0.690** | 0.877 / **0.459** |
| raw | 1111 → 361 | 0.7827 | 0.841 / 0.816 | 0.804 / 0.711 |

Жирным — TNR ниже 0.70. По двум галереям сразу raw даёт средний F1 0.822 против 0.797 у z100 при пороге, подобранном на обоих размерах сразу. Но сам порог raw уезжает с размером: 0.659 на 361 и 0.783 на 1111 (z100 — 4.538 и 4.602); выбранный на 361, на 1111 он даёт TNR 0.459 против 0.687 у z100. Размер закрытой галереи неизвестен, поэтому — z100. То же под формулой 0.7·F1 + 0.3·TNR (она не официальная, в ТЗ её нет) и на 2.2k / 10.8k — `research/honest_eval_results/refusal_formula_a10.md`, разделы 5–6.

## Как выбран порог

- Протокол Андрея: 546 запросов / 361 кадр holdout; 1111 = 361 + 750 кадров test gallery как чужие машины. Отказ «как сервис»: 4 ротации по 25 % машин — у них в галерее остаётся кадр одной камеры, запросы с этой камеры без пары, но с почти-дублем.
- Порог вне фолда (2 фолда по машинам): на фолде выбора — TNR ≥ 0.70 на 361 **и** на 1111, из таких — максимум среднего F1; в конфиг — медиана по фолдам × ротациям, проверка — на отложенных фолдах с ней. Пороги по фолдам: 4.66, 4.54, 5.28, 4.64, 4.63, 4.47, 5.84, 5.03.
- 2.2k, 9.0k, 10.8k для выбора не годятся: в 2.2k пачки почти-дублей тестовых запросов, в 9.0k/10.8k — кадры обучающих машин; обе завышают DBA (на 2.2k +0.060 mAP@10, на 1111 +0.009).

## Запасной план без фона вообще (если FPS с фоном не пройдёт)

Ранжирование то же — DBA k=1, отказ — z100 без почти-дублей только по правилу рамок (`PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=bbox`, `PP_CAMERA_PENALTY=off`), порог 4.9039 (строгий 9.9144): F1 / TNR 0.825 / 0.723 на 361 и 0.687 / 0.740 на 1111 против 0.858 / 0.726 и 0.736 / 0.715 у итога; mAP@10 0.8854 / 0.7489 — то же ранжирование. Правило рамок стоит 0.04 мс на запрос против 1.4 мс у фона.

## Воспроизвести

```bash
python research/closed_gallery.py --data-dir <данные> --env REID_WEIGHTS=<веса a10> --tag a10 --zip dataset.zip
```

Пишет `closed_gallery_a10.json` / `.md` и этот файл; пороги для `REFUSAL_PRESETS` — в JSON, ключ `config_presets`. Около минуты на готовых эмбеддингах.

## Оговорки

- 150 машин holdout: на фолд ~37 запросов без пары, шаг TNR ~0.03; разброс порогов по фолдам ~1 единица z.
- Эмбеддинги — из готовых JPEG-кропов; у Андрея свой кэш, числа сходятся до 0.003 mAP@10.
- Предположение протокола: в закрытой галерее у запроса без пары есть кадр его машины с той же камеры.
