# Режим отказа

Итоговая схема (команда, 18.10): **ранжирование — DBA k=1 без флагов; отказ — сырой косинус (raw) лучшего кандидата без почти-дублей, где почти-дубль = фон ИЛИ правило рамок** (`REFUSAL_SCORE=raw`, `PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=both`), **порог 0.7586** (строгий 0.9302). z100 — пресет по выбору (`REFUSAL_SCORE=z100`, порог 4.3475, строгий 8.8469). Правило рамок в ранжирование не идёт: оно задевает 0.9 % настоящих пар; фон не идёт — см. «Кадр той же камеры в top-1».

## Правило выбора порога — оценка организаторов

Источник — таблица ответов организаторов «Вопросы и ответы Бизнес 7. Фалькон Тех», лист «Объединённые вопросы участников»; номера — оттуда.

- Балл за режим кандидатов — **10 % × (0.7·F1 + 0.3·TNR)** (Q14, Q15). F1 и TNR — micro по запросам, по суммарной матрице ошибок (Q25); решение по запросу — верхний кандидат по confidence (Q19, Q23); TNR = TN / (TN + FP) только по запросам без пары (Q19). Отказ — нет строк query в `candidates.csv` (Q18, Q20); confidence — любая шкала, монотонная по уверенности (Q20, Q26).
- В закрытом тесте у **20 % query соответствующего ТС в gallery нет**; калибровать порог — на своём val-сплите из `train.csv` с ~20 % отложенных ID без пары (Q17, Q6).
- Порог — максимум среднего 0.7·F1 + 0.3·TNR по галереям 361 и 1111, вне фолда; в конфиг — медиана по фолдам × ротациям. Без пары в протоколе 20.0 % запросов.
- **Данные теста при подборе порога не использовались**: ни кадры, ни метки. Галереи — 361 кадр holdout, 750 (+389 кадров обучающих машин) и 1111 (+750 кадров обучающих машин); порог фона τ = 0.68127 и правило рамок подобраны на парах обучающих машин (`research/honest_eval_results/cheap_bg_a10.md`, `dedup_compare_a10.md`).

## Почему raw, а не z100

- **Раньше z100 выбрали на прежнем протоколе** (до 18.10): 4 ротации, правило «F1 при TNR ≥ 0.70», большая галерея — 361 + 750 кадров test gallery. Там порог raw, выбранный на 361, на 1111 давал TNR 0.459 против 0.687 у z100 (`closed_gallery_a10.md`).
- **На протоколе по Q17 официальная формула лучше у raw** — и с порогом, выбранным по своей галерее, и при переносе с одной галереи на другую в обе стороны (таблица ниже: строка — откуда взят порог, столбцы — где проверен).
- **Отвлекатели — обучающие машины**: модель их видела, они сильнее отвлекают, чем невиданные машины закрытого теста, поэтому TNR на 1111 скорее занижен (раздел «Почему на 1111 TNR ниже»).

## Что считается отказом

- `/v1/search` отвечает `refusal: true` (`low_similarity`), если оценка уверенности меньше порога, и `gallery_empty`, если галерея пуста. Иначе — кандидаты.
- Метрика эталона (`candidate_metrics`): у запроса без пары отказ — TN, ответ — FP; у запроса с парой ответ с верной машиной на первом месте — TP, с чужой — FP, отказ — FN. Полнота — TP / (TP + FN). PR-AUC — площадь под кривой точность–полнота оценки для «у запроса есть пара», от порога не зависит.

## Оценка уверенности

- `raw` — косинус (по DBA-галерее) лучшего кандидата из top-100 без почти-дублей.
- `z100` = (s1 − mean(s2..s100)) / std(s2..s100) по тем же кандидатам.
- Почти-дубль для отказа: косинус фонов > 0.68127 **или** правило рамок — сырой косинус ≥ 0.84 и IoU рамок ≥ 0.6, сдвиг центра ≤ 0.3 размера рамки. С порогами рамок Андрея (≥ 0.94, или ≥ 0.85 и IoU ≥ 0.7) — 0.882 / 0.876 / 0.816 / 0.880 на 361 и 0.831 / 0.579 / 0.796 / 0.755 на 1111 (F1 / TNR / полнота / оценка).
- Где в конфиге: `api/app/config.py` — `REFUSAL_SCORE`, `SEARCH_THRESHOLD`, `SEARCH_THRESHOLD_STRICT`, `PP_DEDUP_RANK`, `PP_DEDUP_REFUSAL`; посчитанные пороги обеих оценок — `REFUSAL_PRESETS`.

## Как выбран порог

- Протокол Андрея (`research/local_postprocess/experiments_2026-10-17/eval/head_to_head.py` в ветке `andrew-postprocess-throughput`; в этой ветке его повторяет `research/closed_gallery.py`): 546 запросов / 361 кадр holdout (первый кадр каждой пары машина-камера → галерея); 1111 — 361 + 750 кадров обучающих машин: первый кадр пары машина-камера, 750 пар случайно (сид 2026), без кадров из групп побайтных дублей полных кадров (`leak_audit.json`); 750 — 361 + 389 из тех же 750. Машин из запросов среди отвлекателей нет.

- Порог вне фолда (2 фолда по машинам): на фолде выбора — максимум среднего 0.7·F1 + 0.3·TNR на 361 и 1111; в конфиг — медиана 10 порогов (фолды × ротации), проверка — на отложенных фолдах с ней. Пороги по фолдам: 0.791, 0.756, 0.751, 0.761, 0.751, 0.748, 0.827, 0.822, 0.752, 0.816. Строгий — наименьший с TNR ≥ 0.98 на обеих на фолде выбора, медиана.

## Кадр той же камеры в top-1 считается верным

В эталоне (`research/official_evaluate.py`, копия скрипта организаторов) кадр той же машины с той же камеры (junk) вычищается только из ранжирования: п. 1 протокола, `strip_junk` до усечения до 10 — поэтому он не влияет на mAP@10. В `candidate_metrics` его нет: «есть ли пара» считает `valid_positives` (та же машина с другой камеры), а верность ответа — строка 290:

```python
correct = gal_vid.get(top_gid, None) == row.vehicle_id
```

— только `vehicle_id`, камера не сверяется. Штраф по фону в ранжировании (прежний итог) уводил такие кадры из top-1, поэтому фон в ранжирование не идёт:

| Ранжирование | mAP@10 361 / 1111 | Порог | F1 / TNR / полнота / 0.7·F1+0.3·TNR 361 | то же 1111 |
|---|---:|---:|---:|---:|
| DBA k=1 (итог) | 0.8854 / 0.7678 | 0.7586 | **0.883 / 0.876 / 0.818 / 0.881** | **0.833 / 0.575 / 0.800 / 0.756** |
| DBA k=1 + фон (прежний итог) | 0.8855 / 0.7677 | 0.7586 | 0.847 / 0.876 / 0.807 / 0.856 | 0.733 / 0.575 / 0.764 / 0.686 |

## Почему на 1111 TNR ниже

Отвлекатели — машины, которые модель видела при обучении. У запроса без пары лучший кандидат оценки отказа (почти-дубли выброшены) — такой кадр в 81 % случаев, его средний скор 0.719 против 0.538 на 361: обученные машины — сильные отвлекатели, отказов меньше (TNR 0.575 против 0.876). В закрытом тесте отвлекатели — невиданные машины, поэтому TNR на 1111 здесь скорее занижен.

## Запасной план без фона вообще (если FPS с фоном не пройдёт)

Ранжирование то же — DBA k=1, отказ — raw без почти-дублей только по правилу рамок (`PP_DEDUP_RANK=off`, `PP_DEDUP_REFUSAL=bbox`, `PP_CAMERA_PENALTY=off`), порог 0.7572 (строгий 0.9305; z100 — 4.3542 / 8.8363): 0.884 / 0.872 / 0.820 / 0.881 на 361 и 0.835 / 0.565 / 0.805 / 0.754 на 1111 против 0.883 / 0.876 / 0.818 / 0.881 и 0.833 / 0.575 / 0.800 / 0.756 у итога. Правило рамок стоит 0.04 мс на запрос против 1.4 мс у фона.

## Оговорки

- 150 машин holdout: на фолд ~55 запросов без пары, шаг TNR ~0.02; пороги по фолдам разбросаны заметно.
- Отвлекатели больших галерей — обучающие машины (модель их видела), см. выше.
- Эмбеддинги — из готовых JPEG-кропов; у Андрея свой кэш, числа сходятся до 0.003 mAP@10.
- Закрытый тест: у запроса без пары машины в галерее нет (Q17) — основной протокол; запрос, у которого единственный позитив — кадр своей камеры (Q22), — раздел выше.
- Таблица ответов организаторов в репозитории не хранится; номера ответов — по ней.
